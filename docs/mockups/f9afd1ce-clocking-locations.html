Set up once. Change the radius once, and every company that uses the gate is changed with it.

Assigning does not change. You still choose which locations an employee may clock at, in the same place you do today — the difference is that every location is offered, not only those of that employee's own company.

Two things this deliberately does not include, and why

The address search and map are a separate piece of work. A map means an outside mapping service — an account, a key, a running cost, and your site addresses being sent to that provider. That is a decision to make on purpose, not one that should arrive inside a data change. Raise it and we will cost it on its own.
Timezone is not a field we can honestly add right now. The whole system works in Malaysian time — every attendance day, every payroll period, every leave date. We could store a timezone against a location tomorrow and it would change no calculation. A setting that looks like it does something it does not is worse than not having it. If you have sites in another country, that is a real and much larger piece of work, and worth doing properly.
You have not created any clocking locations yet — so there is nothing to untangle. Centralising now costs nothing in data terms. After a rollout, somebody would have to decide by hand which duplicates across your companies are really the same place.
