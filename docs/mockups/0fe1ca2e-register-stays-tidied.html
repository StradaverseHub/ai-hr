Work sites — what is done, and the one thing we are not doing

You approved removing work sites. Half of that is built. The other half turned out to take something with it.

Done — work sites no longer decide anybody’s public holidays

Work site’s state → Work site’s own calendar → Employee’s own work state → public holidays

Exactly what you approved, and it is built and checked. We verified on your live system before touching anything: 2 employees sit at a work site and both already have their own work state recorded, so nobody’s holidays change by a single day. No work site has a calendar attached. The old paths are gone from the code, not just hidden.

Not done — the register itself cannot simply leave, and we should have seen it sooner

That screen is the only place a work site can be created or edited at all. There is no other door. Delete it and these three stop being maintainable — not broken today, but frozen for good:

The site list itself

8 sites · 2 in use

Two employees are currently posted to a site. The list stays readable and pickable, but no site could ever be added, renamed or retired again.

Branch mapping

0 mapped

We built this for you so an imported branch code could be matched to a site once and then remembered. Nothing is mapped yet — and with no editor, nothing ever could be.

Clocking point links

0 of 2 linked

We promised clocking locations would not be affected. They are not — but a NEW clocking point could never be linked to a site, because no new site could exist.

Nothing on your system breaks today — no branch is mapped and no clocking point is linked. What removal costs is the ability to ever use those again. That is the same kind of decision you just made about site holiday calendars, and we are not going to make this one quietly on your behalf.

The State field goes with it: it now decides nothing, and the line underneath it still tells you it “overrides the employee’s work state for public-holiday resolution”, which stopped being true the moment we made this change. Where we got this wrong

The plan you approved said the register would leave. It also said clocking locations were unaffected because “that link is kept”. We did not notice that keeping the link requires keeping the editor — and we never mentioned branch mapping to you at all. Both are on us.

You were already offered this. The same plan said that if you might want per-site holidays later we would “leave the work-site register in place and simply tidy the screen rather than removing it”. That is what we are now recommending, for a different reason than we expected.

If you still want the register gone, say so and we will come back with what it would take to retire branch mapping and the clocking link deliberately, each with its own decision — rather than letting them lapse as a side effect of deleting a screen.
