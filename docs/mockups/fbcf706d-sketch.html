Before you submit — you are about to add 17 people to this run and reprocess 0 of the 5 already paid.

The 5 payslips already on the run are not touched. The run's totals move by the added people's figures only.

  • Each added person is checked first — no salary on record, missing statutory or bank details. Anyone not ready is named here and held back; the rest go through.
  • The run's employee count goes from 5 to 22.
  • Any loan repayment taken on an added person's payslip comes off their loan balance.
  • Any claim paid on an added person's payslip is marked paid, so no later run can pay it twice.
  • One-off payments already waiting for an added person are picked up onto this run.

3Deliberately not drawn — these stay in words

  • Automatic "Changed" flagging is not in this round. The run already flags someone when their one-off transactions or their attendance change, and ticks them for you. A salary or pay-item edit is not flagged — you tick that person yourself. Drawing a "Changed — pay item changed" row would be promising something this work does not build.
  • Runs set up for a chosen list of people. Ten of your twenty-one open runs are limited to a named group. On those, newly eligible people are still listed but arrive unticked, with a line saying the run was set up for a chosen list — ticking someone widens that list on purpose. The picture above is an unlimited run, where everyone arrives ticked.
  • Someone who is not ready. The plan promises an added person with no salary on record is named and held back rather than silently dropped. Every one of your seventeen has a salary on record, so drawing that refusal would mean inventing an employee — it is described here instead.
