That is the whole screen. Press Create and the record exists, the ID is taken, and HR can walk away.

What Create does, in order.
1. Holds the Employee ID against this person — nobody else can be given it, not the hire form, not a bulk import, not a second draft.
2. Saves the record with a Draft status.
3. Shows it in the employee list straight away.
4. Leaves everything else to be filled in whenever HR is ready.
Where the ID comes from is unchanged. Two of your nine companies have an Auto Running Number setup: SpaceX Sdn Bhd would show the next number X000002 already filled in and greyed out, and Demo Sdn Bhd DEMO000009MY. The other seven, ISEDECOR BINA SDN BHD included, are typed by hand exactly as they are today. Both kinds get held.

The ID is the same A0015 that was held from the first screen. The status is worked out from the dates, not chosen — a join date of 1 September with a three-month probation reads as Probation, and turns into Active by itself on 1 December.

Only now do Family Information, Qualification, Documents and Movement open up, on the normal employee profile.

If a Draft is abandoned. Discard it and the ID goes back when it was the most recent one issued. If somebody has already been created behind it, the number stays spent and the sequence skips it. Your A0001 to A0014 run has no gaps today, so this is the one real cost of holding an ID early.
