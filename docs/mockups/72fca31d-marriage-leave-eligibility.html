We will build this as you described: on final approval, if the status is still Single, it becomes Married in the same transaction, with an audit entry naming the request, the approver and both values. Cancelling an approved Marriage Leave puts it back to Single — but only if that same request is what changed it.

One thing we want to say before you approve it: approval is not the wedding. Marriage Leave is normally approved weeks before the event, so between approval and the wedding the system will record someone as Married when they are not yet. Every figure we checked is unaffected — tax is driven by its own PCB category field, not by this one — so the cost is that the record is early, not that money moves. Your cancellation rule covers the wedding that does not happen. If you would rather the change happened when the leave has actually been taken, reject this and say so, and we will move the trigger.
