The zero that must not be skippedWHY THIS IS NOT A ONE-LINE CHANGE

These two rows look identical on a payslip. Only one of them should disappear.

EmployeeWhat happenedNet payCorrect outcome
A0002 SitiNo bonus was entered for her in this cycle0.00Skip — nothing to pay
A0004 Mei LingTook a full month of unpaid leave; her pay really is zero0.00Must still be processed
So the rule cannot be “net pay is zero”. It has to be “this run has nothing to pay this person”, which is a different question and is asked before the pay is worked out, not after. The good news is that the system already asks it: the draft run screen has a Pending money card that lists exactly who has something waiting in this cycle. We would use that same answer to decide who to skip, so the screen and the run cannot disagree.

And it applies to extra runs only. On a normal monthly run an ordinary salaried employee has no transactions at all — their pay comes from their salary record. Skipping on “no transaction” there would stop paying almost everyone, so this behaviour is for Bonus, Claim, Overtime and other additional cycles, and the normal monthly run is untouched.
