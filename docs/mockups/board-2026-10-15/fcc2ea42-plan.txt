THE SITUATION TODAY

Overtime settings already support reusable patterns, time bands and rounding. They do not yet provide the complete assignment, formula and payroll-mapping workspace described in this request.

WHAT WE'LL CHANGE

- Provide one Overtime Pattern workspace with Basic Information, Employee Assignment, Eligibility, Rates, Formula Builder, Payroll Mapping, and Preview sections.
- Let administrators build grouped conditions, IF / ELSE branches, rates, caps, deductions and rounding using selectable fields and operators.
- Keep overtime eligibility, actual duration, approved duration, payable duration and payment amount separate and explain each step in the calculation.
- Support individual and employee-group assignments with effective dates and explicit priority. Refuse unresolved conflicts instead of choosing an arbitrary pattern.
- Preview selected authorized employee data or entered samples before activation, without creating payroll transactions.
- Map approved results to the selected payroll earning items, prevent duplicate transfers, and retain the pattern version and calculation breakdown.
- Preserve existing patterns and historical results. Corrections to finalized payroll continue through the existing controlled adjustment process.

WHAT YOU'LL GET

HR can configure and test different overtime arrangements in one place, then trace an approved payment back to the attendance, conditions, deductions, rate and rule version used.

GOOD TO KNOW

Caps and deductions apply only when explicitly configured. Existing overtime behavior stays in place until a valid new pattern is deliberately activated and assigned. Formula choices will use supported Attendance, Personnel and Payroll information; arbitrary programming code will not be accepted. Existing jurisdiction and payroll safeguards remain in force.
