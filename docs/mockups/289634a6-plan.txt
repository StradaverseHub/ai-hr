THE SITUATION TODAY

When Payroll History is imported with Update Listed Pay Item Totals, Non-Payable pay items such as BKCAR (Benefit-in-kind car) and BKDRV (Benefit-in-kind driver) are accepted and saved. The system keeps them as the employee's taxable history for that month, and they are counted in the employee's year-to-date income tax when later months are processed, according to each pay item's own PCB setting.

The problem is that they are never shown. Transaction View only lists Non-Payable items that came from payroll processed in the system, so an imported month shows Earnings, Deductions and Net pay but no Non-Payable amounts. The BKCAR and BKDRV rows you saw marked "Regular" with 0.00 come from the monthly payroll processed in the system, not from your import. So the import looks as if it was lost.

Two messages add to the confusion. "Keep existing total" on every line of the import log means those exact amounts were already saved for that month by an earlier upload, so nothing needed to change. It does not mean the line was skipped. And "The previous Income Tax Correction was retained" on reprocessing is a general note that a saved Income Tax Correction for this employee is still in force; it says nothing about the imported items.

WHAT WE'LL CHANGE

- Transaction View, History tab: each imported month shows a "Non-payable amounts" section with every imported Non-Payable item: Pay Item Code, description and amount, for example BKCAR 2,083.33 and BKDRV 600.00. Each line says whether it counts for income tax (PCB), following the pay item's own setting.

- Transaction View, Grid tab: imported Non-Payable items appear under Recorded Items on the same "Monthly - By Import" (or "Bonus - By Import") row as the rest of that import, in the right month, so they sit beside the other imported codes and can be searched and exported.

- Import log: each employee and month shows a plain result above its lines - "Updated", or "No change - these totals were already saved" - so a repeat upload is clearly recognised as already done rather than ignored.

- Income tax: when imported taxable amounts for a month change after an Income Tax Correction was saved for that month, the next recalculation uses the newly imported amounts. The correction stays in the history, and the screen says it was replaced by the new import. If the imported tax details cannot be confirmed, the employee is held with a clear reason instead. The system never quietly keeps the old figure. This is how the system is designed to work today; we will prove it on a copy of your case and fix any path that does otherwise.

WHAT YOU'LL GET

Imported Benefit-in-Kind and other Non-Payable items can be found in Transaction View exactly where the rest of the imported month is, with their tax treatment visible, and the import log says plainly whether anything changed.

GOOD TO KNOW

- We're not touching how anything is calculated, the pay item settings, the PCB tables or rules, the import template or the payroll workflows. Imported amounts are shown as they were saved, never added twice.

- Already imported months show their Non-Payable items as soon as this is released. Nothing needs to be imported again.

- The "Regular" rows showing 0.00 are the system's own processed monthly payroll for this employee. We will check on a copy whether those zero amounts are expected for BD0098, and tell you what we find with the release.
