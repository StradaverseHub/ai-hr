One screen, one period, one place to generate and download. Each format is a self-contained writer behind a common seam, so adding the next one is adding a writer — not reopening the module.

Two of these already exist — and that is what makes the design safe

We have already written the EPF i-Akaun upload file and the PERKESO file. They work, they are checked against real files, and they will be the first two things plugged into this module.

That matters for a reason beyond saving work. A design that claims to support many formats but has only ever been used for one is not actually proven. Wiring the two we already have in on day one is what demonstrates the module is genuinely format-agnostic rather than LHDN-shaped.

⚠️ What we need before we write the LHDN file

A real LHDN file. Not a specification of one. We do not have one — we checked.

This exact thing has already cost us once, on the EPF file. We built it from the field tables in the written spec, without a sample. What our own code now says about that attempt:
“it put the wages where the employer’s contribution belongs and the two contributions added together where the employee’s belongs. A file with the right shape and the wrong numbers in it is the worst kind: it looks valid.”
It was only fixed when the customer sent an actual EPFORMA2 file. We now rebuild that exact file in a test and check it character by character — and we would do the same for LHDN.

So: one real LHDN submission file, for a month you have already filed. Ideally with the figures you filed alongside it, so we can prove ours reproduces yours exactly rather than merely looking right. A blank template or a PDF of the field layout is not enough — that is precisely what went wrong last time.

What we will do meanwhile

We will build the module and put LHDN first in it, as you asked — the submenu, the screen, the period picker, the format seam and the download. The LHDN writer itself is the one piece that waits for your file; everything around it does not.

Salary payments to employees are deliberately last. A bank payment file moves real money to real accounts, and each bank has its own format. We would rather get the statutory files right first and come to that with the same discipline — and a real file from your bank.

Nothing is filed automatically. The module generates and downloads a file for you to submit. It does not transmit anything to LHDN, EPF or SOCSO.
