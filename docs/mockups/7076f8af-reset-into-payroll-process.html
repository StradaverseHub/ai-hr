One more thing worth knowing before you read the rest: resetting a run clears that run's calculated payslips. So the Payslips list on the screen you land on is empty at the exact moment you arrive — there is nothing on it to look at.

1What Reset Payroll does today, and what it will do

Same button, same confirmation, different destination.

You land on one long screen carrying, top to bottom:
  • Generate payslips — the button in the header
  • Draft summary — period, cycle, payment date, headcount
  • Configuration readiness and pre-processing checks
  • Pending transactions  ·  Leavers this period
  • Payroll inputs — plus seven buttons that pull approved amounts into the run
  • Import pay components (CSV)
  • Payslips — empty, because the reset just cleared them

Four of these are the ones you asked to have removed. The screen also calls itself "Step 3 of 3", which is part of why it feels like a stray page.

AFTER
Payroll Process  →  a processed run  →  Reset Payroll  →  confirm
↓
You continue straight into the payroll process:
  • Step 1 — Payroll Information company, month, cycle, payment date
  • Step 2 — Employee Selection search, filter, pick one, several or all
  • Step 3 — Review the checks, and anything you need to adjust first
  • Process Payroll the button that used to read "Generate payslips"
  • Payroll Processing Result succeeded, failed, and the reason

The long screen leaves your path entirely. You still reach a run's payslips the normal way — by opening the run from the Payroll Process list.
