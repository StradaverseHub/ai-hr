VERDICT: Already works   ·   SIZE: Quick

THE SITUATION TODAY

A salary review in AIHR already cannot reduce anyone's basic salary:

- Merit %, promotion % and special adjustment % refuse negative values, both on screen and when saving. The lowest allowed value is 0%.

- There is no box to type a new basic salary. It is always the current basic salary plus merit, promotion and special adjustment, so it can never be lower.

- The data template only brings in ratings and classifications, not percentages or amounts, so nothing can come in through an import.

- When the approved review is sent to payroll, AIHR checks again that each person's salary record is still exactly the one the review started from, and refuses if anything changed in between.

The only real problem is the wording: when someone does try a negative value, the message is technical (for example "meritBp: Too small: expected number to be >=0").

WHAT WE'LL CHANGE

- Any attempt to enter a negative merit, promotion or special adjustment shows "Salary reductions are not allowed in the salary review."

- A final check before the BU CEO can submit, at every approval, and before payroll handoff confirms that each person's new basic salary is at least their current basic salary. Any record that fails is flagged and blocks submission until it is corrected.

WHAT YOU'LL GET

The rule you need is guaranteed by the system at every step, and people get a clear message instead of a technical one.

GOOD TO KNOW

- We are not touching how anything is calculated. The extra final check is a safety net; with today's rules it should never trigger.

- Bonuses and lump sums sent to payroll are always zero or positive amounts.
