THE SITUATION TODAY

The Excel template you download includes reference sheets, one of which lists every employee in the companies you selected. When the upload is checked in the background, the system measures every sheet in the file, not only the transactions. If that employee list is longer than 2,000 people, which happens easily with "All companies" selected, the whole file is refused as "too large", even with only 5 transactions filled in. We reproduced this with the real template.

Separately, one upload can hold at most 2,000 transactions today, and all of them are written in one long step.

WHAT WE'LL CHANGE

We will deliver this in two stages, so the error you hit is fixed first.

Stage 1 - the fix (comes first):

- Only the transaction sheet is checked. The reference sheets (Instructions, Employees, Pay Items, Pay Cycles, Input Types) are ignored when you upload. You can keep them, change them or delete them.

- Transactions are counted by the rows you actually filled in. Empty rows that are only formatted no longer count.

- Error messages say exactly what is wrong and what the limit is. For example: "This file is 12.4 MB. One upload can be at most 10 MB." or "This file has 2,350 transactions. One upload can hold at most 2,000." A wrong template, an unreadable file or a validation problem each get their own message, never "too large".

Stage 2 - large uploads:

- One Individual Transaction upload can hold up to 10,000 transactions (up from 2,000). The file size limit stays at 10 MB.

- Large uploads are written in the background in parts of a few hundred rows. The Import Log shows progress: total rows, rows done, imported, failed and a percentage. You can leave the page while it runs.

- An import shows Completed only after every part has been written. If the server restarts part-way, the import continues from where it stopped without writing any row twice. If it cannot finish, the Import Log shows Stopped with the number of rows already written, and Revert removes them.

- The Import Log's row details are shown page by page, so a 10,000-row import opens quickly.

WHAT YOU'LL GET

After Stage 1, a file with a handful of transactions always uploads, whatever the size of the employee list in the template. After Stage 2, monthly files of up to 10,000 transactions upload in one go, with clear progress in the Import Log, and nothing is half-imported without you being told.

GOOD TO KNOW

- We're not changing the template, its columns, the Pay Item and Input Type handling, the validation rules, how amounts are priced or anything in payroll processing.

- Uploads already run in the background and appear in the Import Log. That stays, including the review step before you confirm the import.

- Rows that fail validation are still listed with their row number and reason, and the valid rows are still imported.

- Uploading the same file again, refreshing the page or pressing the button twice does not create duplicate transactions. This is already guaranteed today and stays.

- Stage 2 applies to Individual Transaction uploads only. The Fixed Transaction import keeps its current 2,000-row limit.

- 10,000 transactions per upload covers about 18 transactions for every employee in a 541-person company. If you regularly need more in one file, tell us and we will raise it after measuring the real speed on your data.
