VERDICT: Partly there already   ·   SIZE: Large

WHAT YOU ASKED FOR

A setting, Attendance File Structure Mapping, where an administrator describes once how each clocking device writes its CSV or TXT file (which column or character positions hold each field, and what its In/Out codes mean), helped by a sample file that is shown but not imported. Then a separate Import Clocking Data screen with a preview, import of the valid lines, and a log of every line not imported and why.

THE SITUATION TODAY

1. Attendance > Import already exists, for one fixed layout only: a CSV of employee reference and date-time ("staff_id, timestamp") pasted into a text box. No other layouts, no fixed-width TXT, no In/Out code.

2. Matching already works as you describe. Card Assignment and the employee's Attendance tab hold one Card ID per employee; the import matches on it first, then on Employee ID or IC. Leading zeros are kept, and one card cannot belong to two employees.

3. It keeps no log. Problems are shown on screen and are gone when you leave the page.

4. Something you should know: it replaces the whole day (earliest punch in, latest out), writing over Clock screen clockings and times already corrected through an approved attendance request.

WHAT WE'LL CHANGE

Attendance > File Structure Mapping (new menu row, beside Card Assignment)

1. A list with Mapping Name, File Type, Layout, Device, Status and Last Used, and View, Edit, Duplicate, Deactivate or Activate, and Delete. Delete only for a mapping never used; a used one is deactivated instead.

2. Today's layout stays as a built-in mapping, "AIHR Standard Template", view only.

3. The New Mapping page has Mapping Name, Description, Device, File Type (CSV or TXT), Layout (separated by a character, or fixed width), Delimiter (comma, tab, semicolon or another character you type), Has Header Row, Character Encoding (UTF-8 by default, also UTF-16 and Windows-1252) and Status.

4. Drop or browse a sample file. Its first 20 lines are shown in columns and kept with the mapping for Edit. Nothing in it is imported.

5. Separated files: drag a field onto a column heading, or choose the column from a list. Both do the same thing.

6. Fixed-width files: type each field's start and end position. A numbered ruler and shading on the sample lines show at once if a field is one character off.

7. In/Out codes: a table of device code and meaning (Clock In or Clock Out), pre-filled from the sample. An unknown code is reported, never guessed.

8. Test with the sample shows what each sample line reads as before you save.

9. Card ID, Day, Month, Year, Hours and Minute are required; Device ID and In Out Code are optional. A missing one refuses Save with "Mapping cannot be saved. Please configure the following required fields:" and the missing names. Names must be unique.

Attendance > Import Clocking Data (the current Import row, renamed)

10. Choose an active mapping, drop the file, press Validate. Nothing is saved at this step.

11. The preview shows the counts and a table of Line, Card ID, Employee, Date, Time, In/Out and Status.

12. Import Valid Records saves the valid lines and skips the rest; one bad line never stops the others. The checks run again at that moment.

13. Times are read as printed, Malaysia time, no conversion. A two-digit year 26 means 2026. Month 13, day 35, 31 September, hour 25, minute 75 or a future date are invalid.

14. Card IDs match exactly (surrounding spaces ignored) against employees employed on that date whom the importer may manage. A card outside your companies is reported as not found, naming no one.

15. A duplicate is a clocking already recorded for the same employee, day and minute (and In or Out, when coded), from any source or earlier in the file. It is skipped and listed, so importing a file twice adds nothing twice.

16. Imported clockings are added to the day, never written over it. The day is then worked out as for multiple clockings on the Clock screen: first in, last out.

17. Without In/Out codes, a day's lines are read in time order as in, out, in, out. An odd number leaves the day open and flagged for review, as the Clock screen does. Uncoded lines cannot add to a day that has Clock screen clockings; they are listed.

18. Days corrected through an approved request, or inside a closed pay run, are not changed; their lines are listed. A day in a processed pay run is updated and that run shows its "needs recalculation" notice. An approved overtime plan is applied as at clock-out.

Import logs

19. Every import gets a log with all the fields and counts you listed. Failed is the sum of duplicates, unmatched cards, invalid date/time and other errors.

20. Status: Successful (all imported), Completed with Errors (some), No Records Imported (none, for example a repeat file), Failed (stopped, nothing saved, reason shown).

21. A log lists every line not imported with its line number, card ID, employee where known and error. Logs are kept; the file is not. The preview warns if the same file was imported before.

Who can do it

22. Administrators set up mappings and import, as today. Mappings are shared by all companies, since a device file does not say which company it is for.

WHAT HAPPENS TO WHAT IS ALREADY SAVED

1. Days imported in the past, Card IDs and all other attendance are not touched.

2. Files in today's format now follow the new rules: they add instead of replacing, skip duplicates and corrected days, and leave a log.

WHAT IS NOT DONE

1. No dragging on fixed-width files. Positions are typed, with the shaded preview to check them.

2. Excel files are not accepted on this screen; device exports are CSV or TXT.

3. One file can be up to about 900 KB, roughly 25,000 lines. A larger file needs splitting into two.

4. Only the three encodings above. Others can be added if a device needs one.

5. Leading zeros are not ignored when matching: 001234 and 1234 are different cards, as they are today.

6. Seconds are not read; clockings are kept to the minute.

7. An imported clocking cannot be deleted from the import log. A wrong time is fixed with an attendance correction, as today.

8. Imports are not checked against clocking locations or registered phones, as today.

9. Files are uploaded by hand. No automatic pick-up from the device.
