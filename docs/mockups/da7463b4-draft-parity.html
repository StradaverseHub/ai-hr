This is not new arithmetic. The active employee’s Profile tab already reads the date of birth out of the NRIC, and so does the bulk importer — deliberately, so that an imported employee’s Age never shows “Not available”. The draft screen is the one place that does not. It will use the same routine, with the same two safeguards: an incomplete or impossible NRIC fills in nothing, and a date of birth already typed in is never overwritten.

ALREADY STORED2. Permanent and correspondence address

Correspondence addressfollows the permanent one

Both address blocks already exist on the employee record — the permanent one the Contact & Address card writes, and a second correspondence block beside it for post that goes somewhere other than home. The draft screen simply does not offer them, so the address has to be added after the employee is activated.

Ticking Same as permanent keeps the two in step rather than copying once and letting them drift — so correcting the permanent address later does not leave old post going to the wrong place.

Why this is smaller than it looks

Nothing new is stored and nothing new is calculated. Every field already exists on the employee record and every behaviour already exists on the active screen. The work is bringing the draft screen to the same place, using the same code rather than a second copy of it — which is what keeps the two screens from drifting apart again.

No existing employee is touched, and a draft saved today keeps everything already entered.
