VERDICT: Partly there already   ·   SIZE: Moderate

THE SITUATION TODAY

When a One Total for the Month import has a row with Input Type set to Amount for a pay item worked out by a formula, such as ONOR - Normal OT, the system saves the number but not the fact that it is an amount. Payroll then treats 105.40 as a quantity and runs the overtime formula on it, so MYR 105.40 becomes MYR 2,468.79. The Edit screen shows the same mistake: Input type Qty, Quantity 105.4.

Importing the corrected file does not help. The duplicate check compares only the number, so the row is refused with "already has ONOR 105.40" even though one line is an amount and the other a quantity.

WHAT WE'LL CHANGE

- One Total for the Month keeps the Input Type from the Excel file on every row. Amount pays exactly the amount typed, and the formula is not used. Qty (or Hours, Days or Units) runs the pay item's formula, giving the same figure as Add new transaction.

- Before you confirm, the import log shows each row's Input Type and the amount it will pay.

- Rows that cannot be imported get a clear message on that row, naming the row and the pay item. This covers an Input Type the pay item does not accept, and a row with both Amount and Quantity filled in. Nothing is ever quietly changed to another Input Type.

- The duplicate check compares Input Type as well as the value, and the message says both. For example: "already has ONOR as Qty 105.40 (pays MYR 2,468.79)".

- If an earlier import already saved the same value the old, wrong way, the new row is refused with "an earlier import saved this as Qty - correct that transaction first". This stops the employee being paid twice.

- Lines already saved the wrong way are not changed automatically. We will run a check and attach to this request a list of imported lines in months that are not yet closed, showing what each pays now and what it would pay as an Amount. HR corrects each one with Edit, which already lets you choose Amount. Closed months stay as they are.

WHAT YOU'LL GET

What you type in the Excel file is what gets paid. An overtime amount stays an amount, a quantity still goes through the formula, and the import tells you clearly when a row cannot be accepted.

GOOD TO KNOW

- Day by Day stays as agreed earlier for this screen: it takes quantities (hours, days or units) only. A Day by Day row with Amount gets a clear message telling you to use One Total for the Month for amounts. Formula-built pay items such as ONOR stay unavailable in Day by Day. If you need either of these, please raise it as a separate request.

- Adding or editing a single transaction by hand already lets you choose Amount for formula pay items. That stays as it is.

- We're not changing formulas, pay item settings, default input types, the Excel templates, or how payroll, PCB, EPF, SOCSO or EIS are calculated.
