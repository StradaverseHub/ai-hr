Leave Configuration — the order of build, cutover and removal. A sketch of the plan for approval. All ten of today’s Leave Config screens are deleted and replaced, in the order below and never before the replacement is proven. Something works at every point, no table is created or dropped, no migration is needed, and the code that turns your rules into a number of days is not touched at any step.

Six rounds, in this order each one deployable and reversible on its own
1

The approval check — built first, before anything moves

The test comes before the thing it tests. For every real employee, every leave type and every length of leave, we record which approver the request reaches today, and keep that as the baseline every later round is measured against.

What you can useEverything, unchanged. No screen changes in this round at all.
2

The new leave type screen — built beside the old one

A brand new screen at a new address, organised as the five questions. Same leave type list, same settings, same saves. Two settings come home to the leave type: sending to payroll, and splitting a multi-day application. Nothing is removed in this round — your existing screen is still the one the menu opens.

What you can useEverything, unchanged. The new screen is there to look at; the old one is still the working one.
3

The rest of the new module — still beside the old screens

The new Company rules screen, gathering four settings that belong to a company and are on four different surfaces today. Plus new pages for entitlement tables, generating, adjustments, importing and the two record screens — same flows, new pages. Still nothing removed. For these rounds a setting is editable on both the new screen and the old one; both write the same place, and round 5 closes it.

What you can useEverything. Settling replacement leave stays where it is.
4

Approval — the new chain screen, and showing what is already there

Tab 5 shows the chain that reaches each leave type. And the rules whose department or position scope no screen has displayed since the old rule list was removed become visible again — to read, not to edit.

What you can useEverything. This round changes no rule; the check must show zero differences.
5

Cutover — the menu moves and the ten old screens are deleted

One screen at a time, ten times: the menu points at the new screen, the old page is deleted and its address becomes a redirect. Every screen’s heading becomes the name the menu gives it — four screens do that today, all ten replacements do — including the busiest one, which still reads “Leave configuration”. The approval check runs before and after every one of the ten.

What you can useEverything. Each screen is only switched off once its replacement is the one you are already using.
6

The last tidy-up

The leftovers, once nothing points at them: the code that remembered which of the old steps you had open, and any wording no screen shows any more. The redirects stay forever.

What you can useEverything.

And we prove the check can fail, before we trust it

We deliberately break one rule in a way that does not error — clearing the leave type from it, which quietly turns a rule aimed at one type into a rule matching everyone — and confirm the check catches it. That exact mistake nearly shipped once before. A check that has never failed proves nothing.

What is kept, and what is actually removed

kept, untouched

  • The code that turns your rules into a number of days — your 297 balance records were produced by it
  • All 261 approval rules, and the tables holding them
  • 297 leave balances · 42 leave applications · 115 recalculation records
  • 45 entitlement tables and your 4 eligibility rules
  • Every leave record: history, adjustments, approvals and the audit trail
  • The four employee-facing leave screens, working after every round
  • Old links and bookmarks — every retired address still redirects

removed — all ten screens

  • Leave configuration (the leave type screen) — page and its 3,367-line panel
  • Approval chain · Replacement leave · Payroll impact
  • Entitlement tables · Generate entitlement · Adjustments · Import leave data
  • Entitlement archive · Balance record
  • The step-and-sub-step arrangement inside a leave type, and the four headings that did not match the menu
  • About 5,800 lines of screen code, replaced by new screens at new addresses

Every old address becomes a redirect, so nothing you have bookmarked breaks. What is not deleted is your data and the code that reads it — your own instruction says not to drop a table that holds both settings and real records, and your leave tables are exactly that. The one thing we keep beyond that instruction is the set of save routines behind the forms: the new forms write the same fields through them, so replacing them would mean writing the same thing twice. Say the word and we will list them for you.

One recommendation, which you can say no to

We will build exactly what is drawn above. This is the one place we say what we would do differently, and if you approve the plan as it stands we will not raise it again. Six of the ten screens — entitlement tables, generating, adjustments, importing and the two record screens — were each rebuilt to a shape you approved within the last year, and nothing in your request is about them. Rebuilding them costs a round each and gives you a screen you cannot tell apart from the one it replaced. Our suggestion would be to rebuild the leave type screen and the approval screen, add Company rules, and move the other six behind the new addresses without rewriting them — the same menu, the same five tabs, four rounds instead of six. Your call, and approving the plan is a complete answer.
