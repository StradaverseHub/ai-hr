THE SITUATION TODAY

Saving BKBOP (BIK-Buyout Payment) with Remuneration Type set to Additional is refused with a message about EPF Bonus 2012, even though EPF is not ticked. The EPF part of that message is misleading. EPF Bonus 2012 is not the problem here; the only thing stopping the save is Remuneration Type.

Behind the message: the monthly tax deduction (PCB) calculation treats every Benefit in Kind and living accommodation line as normal monthly remuneration. It has no way to treat them as Additional remuneration. If we simply let the setting save as Additional, the screen would say Additional while the payslip still taxed it as Normal. That would be wrong, and hard to spot.

WHAT WE'LL CHANGE

- When Payroll category is Benefit in Kind (BIK) or Value of Living Accommodation (VOLA) and Subject to PCB is ticked, Remuneration Type is set to Normal and cannot be changed. A short note beside it explains why: "BIK and living accommodation are taxed as normal remuneration in the monthly tax deduction." You see this before you press Save, not as an error afterwards.

- The error messages are separated. The Remuneration Type message no longer mentions EPF Bonus 2012. An EPF Bonus 2012 message appears only when EPF Bonus 2012 is actually ticked on that item.

- Your BKBOP item will save with Remuneration Type Normal. All its other settings stay exactly as you chose them.

- The same clearer messages appear in the Pay Item import and when payroll is processed.

WHAT YOU'LL GET

The Pay Item screen shows you the rule up front and the message tells you the real reason. BIK items save without confusing EPF warnings, and what the screen says always matches how the payslip is taxed.

GOOD TO KNOW

- We're not changing how PCB is calculated, and we're not changing any EPF tables, rates or settings. EPF Bonus 2012 is already switched off automatically when Subject to EPF is not ticked.

- Treating a one-off benefit (such as a buyout) as Additional remuneration would mean changing the tax calculation itself. That needs a confirmed tax basis first, so it is a separate, larger piece of work and is not part of this plan. If you need it, please raise a separate request with the LHDN reference you rely on (for example the relevant part of the PCB computerised calculation specification) and a worked example of the PCB you expect for one employee and month. We would build and check it against that example.

- Existing BIK or VOLA items already saved as Additional can still be opened and changed back to Normal.
