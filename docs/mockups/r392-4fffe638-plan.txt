ONE CORRECTION FIRST

Your request says existing fixed transactions are already linked to a payroll cycle and that payroll processing uses that link. That is not quite how it works today. The Payroll Cycle on a fixed transaction is only a general label (Regular, Off-cycle, Bonus or Adjustment). It is not linked to any cycle set up in Payroll Cycles, and payroll processing does not look at it at all: a fixed item is paid in every payroll that falls within its start and end dates, and on bonus or off-cycle runs only items set up to pay as bonus are paid. This plan keeps that exactly as it is, which matches your instruction not to change processing.

THE SITUATION TODAY

When HR adds or edits a fixed transaction, the Payroll Cycle list always shows the same four general labels, whatever the company has set up. It does not show the cycle names the company keeps under Payroll > Settings > Payroll Cycles, such as Monthly or Mid-Month. Where a company has several off-cycle cycles (most have three: Off-cycle, Advance Salary and Mid-Month), the label cannot tell them apart.

WHAT WE'LL CHANGE

- On Add New and Edit, the Payroll Cycle list shows the cycle names set up for the employee's own company under Payroll Cycles, in the order shown there. Inactive cycles are not offered.

- Choosing a cycle links the fixed transaction to that exact cycle. The cycle's run type stays part of the cycle's setup and is recorded alongside, as today.

- The employee's fixed transaction list, the Edit screen and the Fixed Transaction section of Transaction View show the linked cycle's name.

- Existing fixed transactions are linked to their company's cycle wherever there is only one possible match. Today that is every one marked Regular, which will show "Monthly".

- Where there is more than one possible match we will not guess. Today that is 2 older Off-cycle records in Demo Sdn Bhd, which has two off-cycle cycles. They keep their current label until someone edits them and picks the right cycle. Records saved with no cycle keep showing as unspecified.

- Saving a change to the amount or dates without touching the cycle keeps the cycle it already had.

WHAT YOU'LL GET

HR picks from the same named cycles they see in Payroll Cycles, and every fixed transaction shows the real cycle it belongs to. Amounts, dates, pay items and payroll results stay exactly as they are.

GOOD TO KNOW

- No payroll calculation changes. Linking a fixed transaction to a cycle does not change which payroll pays it, the same as today.

- There is no setting today that assigns individual employees to particular cycles. Cycles belong to a company, so each employee sees their company's cycles.

- The Excel import for fixed transactions keeps accepting the same Payroll Cycle values it accepts today, and links to the matching cycle when the employee's company has only one.

- A cycle that has fixed transactions linked to it can be made inactive but not deleted, so the history stays intact.
