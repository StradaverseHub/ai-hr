THE SITUATION TODAY

Web Clocking already records attendance, supports repeated clock-ins and clock-outs, and shows the assigned shift and a running worked-time total. It does not capture attendance photos. Device registration and location restrictions currently depend on company and employee settings; they are not compulsory for everybody today.

WHAT WE'LL CHANGE

- Replace the single clock button with separate green Clock In and red Clock Out buttons. Show the current shift, a ticking server clock, worked time and this device's verified registration status. Put the clocking and photo cards side by side on desktop and stack them on phones.

- Require a photo, a registered device and a passing work-location check for every employee portal clock-in and clock-out. This is stricter than today's optional checks. If approved work locations have not been assigned, show what HR needs to set up and prevent clocking; do not quietly allow it.

- Open the front camera only after Clock In or Clock Out is selected. Let the employee take, review, retake or cancel the photo before confirming. Turn the camera off after capture, confirmation, cancellation and leaving the page. If saving fails, keep the captured photo for retry while the camera stays off.

- Save the photo and clock event together, with the recorded time decided by the server when confirmation succeeds. A photo taken earlier never backdates attendance. Refresh the shift, status, worked time and today's newest-first log after saving.

- Put private photo thumbnails beside each event, with an enlarged view on click. Employees see their own photos; supervisors and HR see only the people their existing attendance permissions cover. Keep the original photo evidence when attendance is later corrected.

- Use the same protected clocking process wherever an employee can clock from the portal, including the home-page shortcut, so an old button cannot bypass the photo, time, device or location checks. Other My Attendance menus stay as they are.

WHAT YOU'LL GET

A clear Clock In / Clock Out screen with a photo for every new portal clock event, a reliable worked-time display and an attendance trail that authorised reviewers can inspect. The attached sketch shows the proposed screen before any records or storage are changed.

GOOD TO KNOW

- Approving this plan approves compulsory device and work-location checks for employee portal clocking, including people whose current settings do not require them. HR must register or assign what is missing before those people can clock.

- Existing attendance records remain intact. Old events without a photo say No photo recorded; they never receive a false Photo + location badge. Terminal imports and approved HR corrections remain their own existing processes and are identified separately from portal clocking.

- A photo is attendance evidence, not face recognition or a guarantee of someone's identity. Browser registration and reported location keep their existing security limits; this does not introduce biometric matching or new device hardware.

- The review shows when the photo was taken for guidance. The saved event and photo receipt show the time the server accepted the confirmation. A retry after an uncertain network result returns the first successful receipt instead of recording another event.

PROPOSED SCREEN AND REQUEST CHANGES

Keep /attendance/clock as the menu destination and current shift resolution. Remove the presentation-only shift cycling affordance from this screen: the card states the actual resolved shift rather than implying a shift change. Use two 44px-minimum action targets with 35 percent disabled opacity, not-allowed cursor and accessible status messages. Camera states: idle, acquiring, live, review, submitting, retryable failure, success. Both clock buttons are disabled outside idle/success and whenever prerequisites fail. Capture JPEG at maximum 640px width and quality about 0.8. Stop all MediaStream tracks immediately after capture and on confirm, cancel, route departure, pagehide and component cleanup; retake starts a fresh stream. Keep the captured Blob in memory only until success/cancel/departure. On server/network failure retain it in review; refresh location/device/sequence before retry. Camera denial/no camera uses the requested plain-language error and blocks submission. No gallery/file-picker fallback.

POST /api/attendance/clock accepts authenticated multipart action, photo, lat, lng, accuracy, existing device token and an opaque requestId. Resolve employment only from the session. Reject user timestamps/date/employment overrides. Enforce CSRF/origin protections, body-size limits and server-side decoded JPEG/PNG validation (2MB maximum, bounded decoded dimensions, metadata stripped, canonical JPEG thumbnail). Validate accuracy as finite and nonnegative; retain it as evidence without silently replacing the configured site radius. Device id is not trusted; validate the existing revocable device token against this employment. Recheck compulsory device and geofence rules in the command transaction, including valid accuracy and coordinates, assigned site and effective radius. Browser eligibility is explanatory only. No passing site means no event. Do not change the configured radius or falsify geofencing_enabled to enable this stricter web rule.

GET /api/attendance/today returns only the caller's own current status, actual resolved shift, serverNow, workedSeconds and ordered original web captures plus clearly identified historical/import/correction entries. GET /api/time returns authenticated server time with no-store. Use server timestamp instants for elapsed display and midnight/overnight handling; preserve the attendance engine's shift-day/cutoff convention and keep this counter separate from payable/OT minutes. Work is the sum of completed pairs plus the current open pair; corrections and concurrent sessions trigger a refresh. The present monotonic guard compares whole minutes; use accepted server instants for sequence ordering so separate real events within one minute are not falsely refused, while payable-minute calculations stay unchanged. Server serialises each employment clock command to prevent first-IN races and validates sequence against authoritative state. A unique requestId for this employment replays the original receipt, even if the first HTTP response was lost.

Photo delivery uses authenticated GET /api/attendance/photos/[captureId] with thumbnail/full variants, no-store and non-public identifiers. Resolve the same subject attendance authorization for employee self, scoped HR and existing supervisor/team visibility; test revoked relationships and company/tenant boundaries. No public URLs, shared static folder, profile-photo visibility or generic person-directory grant. A thumbnail is not a separate permission grant. No external photo service or face analysis.
