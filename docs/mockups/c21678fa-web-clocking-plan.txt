THE SITUATION TODAY

Web Clocking supports repeated clock-ins and clock-outs, assigned shifts and worked time. It does not capture photos. Device and location restrictions currently depend on settings; they are not compulsory for everybody.

WHAT WE'LL CHANGE

- Separate green Clock In and red Clock Out buttons, alongside the actual shift, ticking server time and worked time. Clocking and photo cards sit side by side on desktop and stack on phones.

- Require a photo, registered device and passing work-location check for every employee portal clock event. Missing registration or assigned work locations blocks clocking with clear setup guidance.

- Open the front camera after selecting an action. Take, review, retake or cancel before confirmation. Stop the camera after capture, confirmation, cancellation and leaving. Failed saves retain the photo for retry with the camera off.

- Save photo and event together, using the server's confirmation time. Refresh status, worked time and the newest-first photo log. An exact retry returns the first successful receipt; changing the action requires a new request.

- Private thumbnails enlarge on click. Employees see only their own photos; supervisors and HR follow existing attendance permissions. Corrections preserve original photo evidence. An authorised retention purge removes the photo, keeps the attendance receipt and shows Photo unavailable.

- Route existing employee portal clock shortcuts through this same process so they cannot bypass any check. Other My Attendance menus stay unchanged.

WHAT YOU'LL GET

A clear clocking screen and private photo evidence for every new portal clock event. The sketch and proposed data changes are ready for review before anything is applied.

GOOD TO KNOW

- Approval includes making device and location checks compulsory for portal clocking, even where current settings do not require them. HR must complete missing setup first.

- Existing records, terminal imports and authorised corrections remain. Older events say No photo recorded, never Photo + location.

- Photos are evidence, not face recognition. Browser registration and reported location retain their existing security limits.

PROPOSED SCREEN AND REQUEST CHANGES

Keep /attendance/clock as the menu destination and current shift resolution. Remove the presentation-only shift cycling affordance from this screen: the card states the actual resolved shift rather than implying a shift change. Use two 44px-minimum action targets with 35 percent disabled opacity, not-allowed cursor and accessible status messages. Camera states: idle, acquiring, live, review, submitting, retryable failure, success. Both clock buttons are disabled outside idle/success and whenever prerequisites fail. Capture JPEG at maximum 640px width and quality about 0.8. Stop all MediaStream tracks immediately after capture and on confirm, cancel, route departure, pagehide and component cleanup; retake starts a fresh stream. Keep the captured Blob in memory only until success/cancel/departure. On server/network failure retain it in review; refresh location/device/sequence before retry. Camera denial/no camera uses the requested plain-language error and blocks submission. No gallery/file-picker fallback.

POST /api/attendance/clock accepts authenticated multipart action, photo, lat, lng, accuracy, existing device token and an opaque requestId. Resolve employment only from the session. Reject user timestamps/date/employment overrides. Enforce CSRF/origin protections, body-size limits and server-side decoded JPEG/PNG validation (2MB maximum, bounded decoded dimensions, metadata stripped, canonical JPEG thumbnail). Validate accuracy as finite and nonnegative; retain it as evidence without silently replacing the configured site radius. Device id is not trusted; validate the existing revocable device token against this employment. Recheck compulsory device and geofence rules in the command transaction, including valid accuracy and coordinates, assigned site and effective radius. Browser eligibility is explanatory only. No passing site means no event. Do not change the configured radius or falsify geofencing_enabled to enable this stricter web rule.

GET /api/attendance/today returns only the caller's own current status, actual resolved shift, serverNow, workedSeconds and ordered original web captures plus clearly identified historical/import/correction entries. GET /api/time returns authenticated server time with no-store. Use server timestamp instants for elapsed display and midnight/overnight handling; preserve the attendance engine's shift-day/cutoff convention and keep this counter separate from payable/OT minutes. Work is the sum of completed pairs plus the current open pair; corrections and concurrent sessions trigger a refresh. The present monotonic guard compares whole minutes; use accepted server instants for sequence ordering so separate real events within one minute are not falsely refused, while payable-minute calculations stay unchanged. Server serialises each employment clock command to prevent first-IN races and validates sequence against authoritative state. Bind each requestId to the original direction and normalised command intent plus a server-computed photo digest. An exact accepted retry returns its original receipt even when the first response was lost; a reused id with changed direction, photo or command intent returns a conflict and writes nothing. Validate and compare identity before replay, without reinterpreting an accepted retry as a new clock action; enforce current ownership and authorization on receipt retrieval. A retry cannot overwrite the accepted time, device or location attestation. Before first successful acceptance the retained in-memory photo can be submitted with refreshed location; after acceptance the command intent is frozen. If uncertainty prevents matching the accepted command, reconcile its receipt before creating a new request id.

Photo delivery uses authenticated GET /api/attendance/photos/[captureId] with thumbnail/full variants, no-store and non-public identifiers. Resolve the same subject attendance authorization for employee self, scoped HR and existing supervisor/team visibility; test revoked relationships and company/tenant boundaries. No public URLs, shared static folder, profile-photo visibility or generic person-directory grant. A thumbnail is not a separate permission grant. No external photo service or face analysis.
