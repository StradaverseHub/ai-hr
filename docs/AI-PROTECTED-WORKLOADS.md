# Protected AI workload variants

These source integrations describe eligible inputs, not provider activation, specialist approval or
release acceptance. Native permissions, current-source replay, configuration and privacy review,
spend admission, deterministic adjudication and human confirmation still apply. The model does not
calculate payroll, rate people, approve records or supply verified HR facts.

| Feature | Available protected assistance | Native screen / remaining input |
| --- | --- | --- |
| Provider evaluation | Fixed published synthetic echo and tool-cycle fixtures | Arbitrary provider conversation state is not forwarded. |
| Module-agent evaluation | Fixed published read-plan and conversation holdouts | No arbitrary caller-labelled “synthetic” prompt or HR source is accepted. Historical results retain their original source identity. |
| Personnel import | Select among canonical fields identified locally for each opaque column | Unknown private headings remain unresolved; no rows or raw headings leave the source owner. |
| Readiness reminders | Choose a tone for a closed missing-record category | Native templates write the reminder; sending still follows the existing notification policy. |
| Claims triage | Suggest asking for detail when the native source finds a missing or brief description | Category, expense date, subject and financial merit are not inferred from withheld narrative. Longer descriptions retain native review. |
| Payroll hypotheses | Rank a candidate already supported by native feature adjudication, or abstain | No actual values, identity or asserted cause is supplied by the model. |
| Payroll detector explanation | Select recorded field references; display exact authorized values locally | Unsupported detector facts do not become model explanations. |
| Pay-rule drafting | Confirm a locally parsed kind; restore the human's parameters locally | Unstructured rule meaning and formula dependencies use the native rule editor. |
| Report drafting | Arrange explicitly selected canonical column IDs | Private filters and unstructured report requests use the native report builder. |
| Feedback planning | Arrange four implementation phases with the reporter's request attached locally | This is an outline for human planning, not a semantic implementation design inferred from private notes. |
| Performance narratives | Order existing authorized passage references into an editable source outline | Raw-note interpretation, documents, images and individual-rating inference remain unavailable. |
| Performance rewrite | Paragraph/bullet layout with original words retained locally | Semantic rewriting and generated forward-looking assertions remain unavailable. |
| Performance guide/admin | Select current authorized fact references or existing native links | No invented facts, links, reports or administrative commands. |
| Calibration | Parse a narrow explicit read request locally and confirm its action | Native review/confirmation owns every sensitive decision; ambiguous names refuse. |
| Performance draft commands | Parse explicit human-authored fields and exact local targets | No inferred ratings, submission, approval or employment decision. Original UTF-16 spans remain local. |

## Examples for input helpers

Pay-rule examples are `fixed`, `10% of basic`, `per day: 50`, `per hour: 12.50`,
`quantity: 3 rate: 25`, and `value: 120 cap: 100`. These are declarative inputs; the native rule
validator still owns valid ranges and proration conflicts. Values never enter the model request.

For a leave-balances report, use `columns: name, balance`. Only canonical fields available in the
selected native dataset are eligible. The model can reorder that exact set, not add filters or fields.

For layout, use `format as bullets`, `format as a paragraph` or `polish`. The last option chooses
paragraph layout; it does not paraphrase the person's words.

Calibration examples are `explain: Exact Person Name`, `distribution`, `framework`, `curve gaps`,
and `prepare lock`, optionally `for Exact Unit Name` for the latter summary requests. Names resolve
only against the fresh authorized local roster, and ambiguous names refuse. Preparing a lock is not
locking a calibration.

Explicit Performance draft examples are `remark: my own words`, `log evidence: my own words`
on an eligible journey, `aspiration: my own words` on an editable career, `add KPI: Exact Library
Title`, `remove KPI: Exact KPI Title`, and `weight for Exact KPI Title: 20`. Current workflow state,
source authorization, original-text span validation and native proposal adjudication remain mandatory.

The canonical descriptor and availability owner is `lib/ai/provider-workload-policy.ts`. Its runtime
imports are server-side; client screens should receive serialized availability from an authorized
server boundary. An unavailable variant must explain the supported input and link the native workflow,
rather than present a generic provider failure or claim that all free text has been restored.
