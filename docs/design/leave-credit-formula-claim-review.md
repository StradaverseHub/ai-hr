# Duration-only Leave Credit review

The existing banking and financial write paths remain authoritative and unchanged. This read-only projection describes a claim; it neither grants a credit nor establishes statutory eligibility, consent, policy permission or a cash amount.

`leaveCreditClaimReviewTx` composes the existing formula duration proof and source-company tier owner. Legacy dates explicitly return `basis: legacy`; no missing, failed or pending response means legacy. Non-working formula days compare the entered window's counted minutes with the recorded bound, refusing an excess without clipping or inventing credit. Ordinary formula days use the existing shared allocation/window intersection before the existing break/grace/tier step. Refusals carry finite reason codes, never raw error messages. No salary, price or cash evidence crosses the boundary.

Employee identity comes from the server session. HR uses the existing administrator/employment fence. The approver review keeps the original stored claim, separately labels reviewed facts, blocks the convenience approval button when unresolved, and reuses the existing decision action. The decision/banking owner still revalidates everything and can refuse later. Source day-kind mismatches become stale; source/calculation revision is shown as evidence. The client keys async responses by subject, date and entered window and discards responses from earlier contexts.

The pending queue reads at most 200 request heads and 5,000 claim lines. Both the queue and each mounted form explicitly run at most one proof action/transaction at a time. The queue deduplicates exact employment/date/window keys and reuses a legacy basis for that employment/date only after an owner explicitly returned it. The canonical adapter exits before formula evaluation for legacy dates. The form replaces queued stale contexts while an existing request finishes, so rapid input changes cannot enqueue simultaneous proof transactions. Each canonical review runs in its own short transaction, so proof locks are not retained for different employees in one transaction. The queue is a preview across reads, not a financial snapshot or a bulk approval authorization. The worst case is still 5,000 unique short proof transactions before the Approvals page renders; deduplication does not establish acceptable latency. Throughput, latency and concurrency behavior have not been measured. The visible tier figure is explicitly a duration-based tier estimate, not a promise that overlap, started Payroll, consent or other banking guards will pass.

Source regressions cover the actual shared employee/HR table's 601-minute claim versus a 60-minute formula, explicit legacy self-declaration, absent/failed/late review responses, six-locale notices, ordinary-day intersection, stale source, unchanged pending claim and atomic banking refusal. Existing legacy DOM fixtures explicitly return the legacy basis.

A practical negative control is to keep the new owner and fixtures but restore the table's old unconditional `leaveCreditWindowCredit` figures and remove its unresolved-review block. The named 601-versus-60 table cases must then fail on the promised credit/enabled submit. Restoring the manager page's `statusText[status]` fallback must fail the separate Day Type wiring regression. These controls have not been executed.

Types, database regressions, role/privacy tests, real browser journeys, stale-response concurrency and the negative controls remain unrun until the parent coordinates a resource window. No schema or migration is added.
