# Leave Configuration — the proposed structure

> Historical summary. Full original: `git show d8b2bac9705fd8fbc4d3eb500262b19858bf297d:docs/design/a6fe37fc-leave-config-ia.md`. Verify current source and evidence before acting.

## Retained design contract

Reorganize configuration around the leave type, keeping canonical calculation and approval owners. Preserve every editable field, action/tri-state marker, permission and history. New screens precede removal; old addresses redirect with their replacements. Employee leave, tracker, balances and records remain available throughout. Company-wide settings have one destination; entitlement tables and eligibility rules keep one stored owner and one matcher.

Separate eligibility, entitlement, application conditions and approval routing. Table membership and service bands are facts, not newly calculated entitlements. Approval null/wildcard semantics must survive migration. Preserve historical/specialist inputs and distinguish genuinely unrepresented configuration from a request to redesign the engine.

The table retains the full original function mapping and later placement corrections. It is a historical design account: verify each destination against current routes rather than assuming a proposed screen is pending. See the [migration sequence](a6fe37fc-migration-order.md), [original audit](../audits/a6fe37fc-leave-config-audit.md), canonical owners and current regression tests for reconciliation.
