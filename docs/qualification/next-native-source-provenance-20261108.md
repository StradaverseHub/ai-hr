# Native Next source-copy provenance

The authenticated same-run build packet supplies the candidate/source SHA, controller identity, canonical selected preparation and package/lock hashes, exact compiled format2 archive/manifest bytes, build ID and external sharp/fontkit package identities. It does not contain every tracked Git file or attest every file in this native job's installed node_modules. This difference must remain explicit.

The prepared `scripts/performance/next-source-proof.mjs` collector runs Git only as the actual nonroot wrapper with a fixed sanitized environment, fixed binary/commands, exact HEAD and clean tracked state. It collects the exact candidate commit and bounded raw tree objects. The root fixture uses the pure `deploy/admission/next_source.py` verifier to hash the Git objects itself, anchor the root tree to the trusted candidate SHA, derive every recursively reached path/blob/mode, and reject missing, duplicate, foreign or malformed trees. Caller-provided path lists and a HEAD text marker cannot substitute for that proof. No Git or application code executes as root.

The actual package copier must subsequently read source through the canonical pinned descriptor primitive, verify each regular file's Git blob hash/mode and stable descriptor/path identities, and copy only those expected tracked files. Current tracked source contains no links or submodules; those deliberately refuse rather than receiving a general link exception. Node modules are separately owned by the trusted hosted lock-bound installation. Their real copied closure must use the unchanged descriptor/pnpm resolver, reject escapes/special files, copy stable bytes into independent root-owned regular files, and bind the complete resulting dependency inventory. The original packet independently verifies the compiled files and the two external-package identities. This is a development native fixture boundary, not an authenticated operator release package or installation grant.

Prepared synthetic Git controls are exposed by the ordinary no-DB selector `test/runtime-next-source.test.ts`. They derive nested path/blob/executable facts from actual Git object hashing, demonstrate changed blob identity, and refuse changed/missing/duplicate/foreign objects, a fabricated path list, traversal, links and submodules. They execute no Git, SQL, Node application, privileged operation or runtime. The collector and controls have not run locally. Actual descriptor copying, native closure capture and all application/ingress journeys still require the subsequent root fixture and hosted qualification; this primitive supplies no native PASS.
