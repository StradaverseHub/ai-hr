# Dedicated UID fixture: numeric identities and actual root closure

SOURCE ONLY, exact d283 child. Original d283 remains frozen and unexecuted.
Root and independent FULL review precede any publish or standard hosted fixture
behavior. No package/application/DB/native kernel/test execution occurred locally.
This component grants no normal NoDB, six-operation, API or deployment authority.

The predecessor census read all Uid/Gid slots but selected actors only by Uid.
An unregistered numeric GID can already be a primary, saved, filesystem or
supplementary group of another UID. The new shared identity precondition checks
all four Uid and Gid slots plus Groups. It runs before protected allocation and
again immediately before each user/group deletion. A GID-only foreign actor
causes refusal. No census result authorizes a signal, even for the dedicated UID.

The predecessor finish step killed a recorded root supervisor/monitor, then
considered only UID62000 actors. A fixed command still executing load_state or
Node hashing before restrict() could remain UID0 after those anchors died.
Removing the account with an empty UID census would lose that live root family.
The old argv/JSON root-family reconstruction and global UID termination are gone.

Each root role now starts in a dedicated, single-threaded, childless root owner
with default SIGCHLD and its own subreaper bit, outside unchanged shared K. It
spawns only fixed protected helpers, binds its fresh actual child with pidfd and
keeps that child WNOWAIT-reserved. During work it captures live actual parent
chains plus direct adopted children. Reparenting inside the held family is
accepted only under its own actual owner or another live held parent identity.
The actual pid/start and held pidfd identify each owned process. Arbitrary root
processes, GID matches, argv and serialized ancestry never create ownership.

Work stays ten seconds and one cleanup allowance stays six seconds, inside the
same first-step 1800-second job anchor and original artifact/account reserve.
No extra six-second retry or nested outer cleanup budget is added. The root
owner captures/stops the closure while its fresh supervisor PID remains
reserved, repeats capture until every live member is stopped, then signals only
held pidfds, descendants before the supervisor. It captures adopted children,
waits for all bound exits, reaps adopted children and finally reaps the reserved
fresh supervisor. The global fixture closure is capped at 128 held identity
rows across all completed roles and the active role. No shared K byte changes.

The root owner writes a private O_EXCL closed receipt only after that native
sequence, tied to its actual owner, child identity/exit, source, run and operation.
The private root-owned directory and protected code prevent a candidate hook
from minting it. Normal success also refuses any live descendant remaining after
the supervisor exits, even if outer cleanup later kills it. Observation errors,
unknown ancestry, row/deadline exhaustion or source/publication failure retain
unavailable facts; they cannot produce a closed receipt or account-removal claim.
This receipt is component bookkeeping, never a portable API/native issuer handle.

finish checks every started role against its closed receipt and requires all
UID/GID/group actors absent. It does not reconstruct or signal root families.
A missing closure refuses before account deletion, even with an empty census.
Any owner death that prevented closure leaves completion unknown. Existing
private failure prefixes and unavailable publication remain intact; no global
root cleanup is attempted as a fallback.

  subsequently dispose them; the identity census never kills either actor.
- The real root K supervisor starts a fixed command before UID drop. That command
  creates a UID0 follower in another session. Only after the outer root owner has
  captured the follower's actual pidfd and acknowledged it does the control kill
  its own live bound K supervisor/monitor. The outer owner must capture/adopt and
  close the surviving root follower before reaping its reserved supervisor. The
  expected interrupted-K failure remains a failure; no fake K completion is used.
