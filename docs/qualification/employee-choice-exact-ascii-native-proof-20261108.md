# Isolated exact ASCII native proof

Unexecuted proof-only successor of approved design
`2049054e88202fdcacf31c6a50ffef391634daea`. The application, existing employee
lookup SQL/owner, schema, compiler, CI admission, notification inventory and
profiles are unchanged. No function, extension, grant, migration or provider
operation is installed or invoked. Production remains held.

The two new selectors contain eight pure cases and three ordinary native cases:

- `test/employee-choice-ascii-observation.test.ts`: pinned complete Unicode
  derivation, unknown-schema/conditional/range refusal, Unicode barriers,
  complete scalar framing/corruption, query routing model, and three deferred
  ownership/cancellation/compound-failure controls.
- `test/employee-choice-exact-ascii-proof.test.ts`: all 1,112,063 database-valid
  scalar records, 81 Final Sigma contexts plus four adversarial vectors, and
  130 literal-query vectors plus forbidden/fallback and direct native refusals.

Run these through existing focused hosted checks only after root and independent
source review. The native file imports the actual `postgres` driver and is an
ordinary DB test, not a focused-only or cluster-global singleton. It performs
only built-in read-only SELECTs as the real `ai_hr_app` LOGIN in its canonical
loopback worker database, with repeatable-read/read-only isolation,20-second
SQL limit,300ms locks,2-second connection startup and the unchanged30-second
case/hook limits. The owner also checks a monotonic30-second case deadline and
never permits later work after uncertain cancellation/close. Standard runner
resources, original lookup1-second targets and all existing plans are untouched.

Official Unicode17 primary files and their unchanged distribution license are
vendored under `test/fixtures/unicode-17.0.0/`; expected complete file lengths
and SHA-256 values are checked before parsing. The parser preserves identity
defaults, checks paired range records, enumerates all16 conditional rows, and
refuses any unreviewed condition instead of extrapolating future support.
Native regex observation and the independent procedural Node observer compare
ASCII runs separated by non-ASCII barriers, not entire Unicode lowercase text.

One fixed native transform fragment is inserted at exactly one reviewed token
in each fixed SELECT. No caller supplies SQL, a function name, an identifier or
a rule registry. Scalar records are int32 code point, int32 UTF-8 byte length,
then exact observation bytes. Every record's order/count/shape is checked before
whole-buffer `Buffer.equals`; hashes are additional evidence, never substitutes
for comparing all bytes. Missing, repeated, reordered, changed, malformed and
partial records have negative controls. Native records and independently
generated Node records are both retained as distinct actual `.bin` members.

The native context query also deliberately removes the U+0130 combining-dot
barrier and omits the Kelvin mapping; its positive controls require those broken
expressions to disagree with JavaScript. Full81 contexts cover cased,
case-ignorable, overlapping U+0345, long ignorable sequences, uncased and
supplementary neighbors. Node's actual final/nonfinal sigma result is separately
asserted, although either non-ASCII result is the same ASCII barrier.

The query adapter is explicitly a **proof-only routing model**. It executes the
actual native expression for supported ASCII data and actual JavaScript matching
for fallback data, asserting that NUL/lone-surrogate/non-ASCII input and altered
runtime-version profiles never reach its native query. It does not wire or
qualify an application route. Real application adoption and its full population,
authority, metadata, facets, complete IDs and performance proofs remain a
separate later experiment.

The experimental runtime tuple is source-derived Node22.23.3, ICU78.3,
Unicode17.0 and V8 `12.4.254.21-node.57`. The V8 tuple follows the official
[version header](https://raw.githubusercontent.com/nodejs/node/v22.23.3/deps/v8/include/v8-version.h)
and [Node embedder suffix](https://raw.githubusercontent.com/nodejs/node/v22.23.3/common.gypi).
The earlier design's ICU-data caveat still applies: actual versions must match,
then every scalar/context assertion must pass. Unknown runtime tuples fail this
proof rather than being sampled or declared compatible. Actual runtime metadata
is captured even if that experimental version admission fails.

Each native case hashes the actual Linux `/proc/self/exe` kernel descriptor
with64KiB reads under a256MiB file bound, verifies its device/inode against the
configured executable, and requires stable identity/size/timestamps and the same
digest after the work. Complete runtime versions and all owned source hashes
are also stable before/after. This records the **actual binary that ran the
proof**; it is not a caller-issued installation capability. No future binary
digest or application permission is preapproved by this source.

Artifacts live under the existing authenticated runner evidence directory in
`employee-choice-exact-ascii-proof/`: three JSON reports at most1MiB each and two
scalar members at most16MiB each. Member writes are exclusive0600, fsynced,
descriptor-read back with a hard expected-length-plus-one bound and byte-compared.
The normal focused ZIP64MiB limit is unchanged. The corpus alone has a reviewed
worst-case bound below16MiB; actual complete sizes and hashes remain to be
measured. No member is clipped, sampled, regenerated in place or truncated.

No local runtime, application tests, compiler or build was run. All prospective
counts, durations, memory use and native semantics remain unqualified until the
frozen hosted chunks finish and their actual API/artifact evidence is verified.
