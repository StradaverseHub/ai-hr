# Native Next preflight integration

Development candidate only. Staging and production are unchanged. This joins
the frozen installation witness/Git metadata boundary and actual Next fixture
through normal merges. The protected bootstrap/order repair is a mandatory
contributing component. No source-only check constitutes actual boot acceptance.

The integration aligns the closed bootstrap schema, root-owned Node0555,
public receipt/event0444, bounded controller inventory and existing native role
prerequisite handshake. Ordinary and focused paths retain their original event,
controller and plan-observer locations. The native path revalidates the sealed
event hash and fixed protected controller, and reconstructs role membership
through the protected finite role-plan operation. Runner-owned prerequisite
receipts keep their existing strict ownership checks. No role, URL or source
identity check is removed.

The installation capture precedes the classifier. Source-bound PDF preparation
now follows that capture in the same owner invocation; its child receives no
platform or database capability. The native test child receives the existing
canonical disposable URLs only after owned host/DB admission. Its actual Node
must be the protected executable, while the package copy is independently bound
to the original pre-install executable bytes. Each sealed helper Git blob must
also match the cryptographically verified candidate source Merkle tree.

The native source footprint includes the actual seed/browser, protected owner,
setup/workflow and role prerequisite adapters. Existing ordinary/focused role
controls remain; native models additionally reject foreign bootstrap fields,
mutable old event locations and changed sealed event bytes. Models are explicitly
injected observations and do not claim an actual protected host.

After independent closure, run the complete controller/source-plan checks and
focused bootstrap, build-binding, dependency-inventory and role controls. The
first actual singleton must consume its own successful same-run build and prove
two real workers, password/TOTP, hydration, nonempty Home/payroll and conservative
admission/reclamation. It is a boot preflight, not full module/load qualification
or deployment authority. All remaining architecture gates remain in force.
