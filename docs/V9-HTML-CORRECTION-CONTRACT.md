# V9 HTML alignment contract

The supplied admin HTML owns labels, grouping, active flows and content geometry. The handover prose supplies context; when they disagree, executable HTML behavior governs. AIHR owns the authenticated shell, themes, company scope, persistent case/Personnel owners and delivery history. No prototype persona becomes an account or grant.

The module has three groups and nine leaves: Onboarding (New Joiners, Checklist Management), Offboarding (Leavers, Offboarding checklists), Configuration (Templates, Workflows, Onboarding & Offboarding Settings, Assignment Groups, Module Access). Tasks and Request Records remain shared Inbox destinations. The normal AIHR root and selected Classic, Monolith or Atelier theme render all shipping V9 routes.

## Checklist definitions

New checklist precedes the Owned by you / Other checklists selector cards. Cards show role, matching rules, tasks, population and owner. Duplicate creates new checklist/task identities owned by the initiating actor. Only the current owner can transfer ownership or delete; transfer requires an available user with access to the same module. Existing configuration authority remains independently required. Deletion requires explicit confirmation and may remove the final checklist: new cases then have equipment/access or return/revoke work without checklist tasks. Pending overrides fall back to automatic matching. Active native confirmed snapshots and submitted offboarding snapshots remain retained; native Draft reconciliation continues through its existing owner.

## Explicit document replacement

Publishing never replaces a generated document. Regenerate uses the version currently in use on an open pending/submitted case and creates an unsigned draft with current source values. Completed, acknowledged, signed, countersign, withdrawn and superseded documents cannot regenerate. A live delivery reservation blocks replacement. A released copy is retained as superseded, linked to its replacement and audited. An unreferenced unsigned draft can be removed; a draft referenced by any delivery history remains superseded so frozen transport references remain intact. Supersession changes the instance, so the existing exact-copy retry guard refuses replay; any updated delivery requires its existing reviewed-preview flow. The new copy is not automatically sent. Native documents continue through the canonical native revision/private-history writer.

## Filtered request CSV

Export uses the same authorized, filtered, ordered rows as the list. It contains Type, Request, Case, Person, Job title, Business Group, Join date / last working day, Status, Done, Items and Handed over / cleared. Item names and not-returned markers are retained. The existing CSV serializer handles quoting and spreadsheet formula protection. The export panel updates as filters change.

## Role Profiles source correction

The artifact retains legacy Role Profiles markup and a `goProfiles` handler, but no markup binds that handler. Its active `profileFor` returns catalogue `matchedKeys`, rather than selecting a stored profile bundle. Thus absence of managed profiles is not an active-flow gap in this HTML revision. Do not add a menu or activate role-bundle provisioning based on the older handover section. Catalogue matching remains the sole proposal source.

## Verification boundaries

Source inspection, component behavior, database authorization/history checks, hosted compiler/build, rendered fixture screenshots and staging tenant acceptance establish separate claims. An installation showing Set up workspace is not proof of operational page acceptance. Initialization changes shared business configuration and requires a reviewed target/diff before execution. Focused checks alone do not authorize release; use the repository's exact-source release verification and shared staging lease. Production remains separately authorized.
