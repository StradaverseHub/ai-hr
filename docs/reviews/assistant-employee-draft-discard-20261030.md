Historical proposal preserved for review provenance. The current development design and verification status are in [the implementation review](assistant-employee-draft-discard-implementation-20261030.md).

Status: pending independent architecture/proof review. This change contains a typed contract, pure authored contract/transport tests and this map only. It adds no runtime adapter, registry entry, tool, route, mounted control, native writer, SQL, journal allocation or completion proof. No local execution or hosted result is claimed. The base is `44111437c4e831f92be348a946d1954562c3e0e5`.

## Proposed boundary and public shape

Select one existing saved `draftId` and its actual assigned `companyId`; require explicit human consent to delete that saved draft row and its captured input with no application undo. This is not a promise to purge all PII from audits, history or backups; native events retain reserved code and existing audit records may retain labels. “Saved” means a persisted `public.employee_draft` row, not an invented status column. Unassigned drafts and ANY linked onboarding case require the native workflow, including cancelled/archived cases and cases retained while Lifecycle/configuration is off. Module-off metadata is not an absence witness.

The human-only review carries draft/company IDs, authorized company name, the dedicated stored draft label, the saved-row deletion/no-application-undo consequence and a bounded reserved-code outcome. The label is not extracted from private `data`; no other captured person/family/pay/bank fields are projected. These display values are for the authorized human and are not model/provider input. Model-side selection, if later approved, remains the closed two-ID selector. No current counter, increment, configuration ID, other caller/author identity, raw draft object, native error detail or event/deletion witness belongs in these DTOs.

The contract has prepare/reopen/retire response validation and a strict confirmation INPUT. It deliberately has no Completed/Receipt schema or confirmation-result representation. Developer uncertainty is documented here, not encoded as a product `native_proof_pending_review` response. The `PrivateSource` interface contains current USER, nullable actor PERSON, tenant/draft/company and exact-format opaque draft/counter/context commitments only; the names are provisional source-binding interfaces, not an implemented hash/proof algorithm. No builder or commitment authority is exported. Public reviewedDigest is not a raw source-row hash.

The prospective outcomes mean only an actual successful native preview's result: `no_reservation` has no nonempty held code and no numeric reservation; `unreserved_code` has a nonempty saved identifier with stored `reserved_number` NULL, so the saved identifier is removed with the draft and the native owner leaves the sequence unchanged. This is a valid native shape, including manual code entry through `createEmployeeDraftWithReservedCode`, not a malformed reservation. It is classified from actual stored source, never the identifier's prefix, digits or presumed manual origin. `released_tip` means a real numeric reservation's native release actually updated its selected counter; `retained_gap` means a real numeric reservation's held code was not released and the native command otherwise succeeded. Other unsupported combinations, such as a numeric reservation with no held code, may still use `unsupported_reservation_shape`; the native owner itself returns false without a truthy code, so no gap/release is invented. No counter arithmetic, release decision, future ID or fixed timing is derived by the contract. Out-of-bounds private source/display input is handed off rather than silently truncated.

## Lock, cleanup and proof dependencies

Default discard reads then acquires audit/onboarding before its DELETE statement acquires Access. Save/create/activation already acquire Access earlier; counter/config writers include config-row-to-audit and config-delete-to-draft-FK/Access orders. Access followed by BLOCKING audit can therefore deadlock with ordinary discard, even with counter NOWAIT. Only the Lifecycle owner's exact canonical lock/context extension may resolve the interval; no private parallel coordination key or local lifecycle query is introduced. Native preview must preserve actual RLS refusal and held live counter state. Locks needed for preview/final source stability must outlive rollback-only preview savepoints.

Coordinator's current cleanup direction defers ALL pending draft activation/discard ciphertext retirement to COMMIT after the current native completion. There is no immediate other-user retirement. Activation's current body remains until 0714 completion; current discard must retain its own body until independently proven completion. Actual native GUI delete/activation must also commit with remaining bodies retired. Other users may have arbitrarily many reviews; the maximum of two applies only to one USER's one-per-kind pending slots, not global fanout. Install bounds before commands and retain them through COMMIT/deferred work. Contention or any deferred failure may abort the whole native transaction; no fixed-time promise, skip-locked partial cleanup or silent truncation is approved. Exact owner implementation is still pending.

A future private witness on the existing review ledger must arise only from actual exact-table DELETE, not app-controlled state, GUC, a SELECT, matching absence or forged native event. Top-level tuple-XID and native event/counter proof, child-savepoint refusal, replay/historical recovery, generic expiry/erasure clearing, retained privacy and deferred cross-caller retirement remain independent proof-review decisions. This contract does not settle them. No numeric migration filename/index/timestamp is reserved or claimed.

## Authored checks and later integration

The pure suite rejects actor/value/identity/counter injection, private response fields at every layer, foreign draft/company/action substitution, reordered-key false negatives, operation confusion, contradictory release labels, valid unreserved identifiers of numeric-looking and nonnumeric formats without origin inference, unbounded held codes, malformed/zero-length time intervals and UTF-8 budget overflow without Unicode normalization. It distinguishes review retirement from native draft deletion and rejects every attempted confirmation result. These are authored checks only; no local test/collection/compiler/DB/build/server was run.

Only after root/coordinator review may this source-only patch be frozen. Root owns final source-manifest regeneration and any later publication/hosted verification. Native source, SQL/journal, registry, transport adapters and mounted UI remain outside this patch's ownership.
