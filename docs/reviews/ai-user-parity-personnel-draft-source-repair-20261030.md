# Saved-draft activation source stability


## Criteria coordination counter repair

The existing native `app.lock_system_label_criteria` increments each kind's epoch whenever it obtains the physical coordination row. The Assistant interval and rollback-only activation preview both acquire that lock outside the preview savepoint. Hashing the counter therefore made an unchanged saved draft stale after the preparation request committed. The source now fingerprints the actual selected department's `label_company_assignment` rows, ordered by company ID and row ID. Every native Criteria lock is retained, alongside the existing company/department snapshots, native eligibility checks, payroll/templates/eligibility configuration and exact native pay/leave preview. The supported subset contains no position, cost-center or business-unit selection. The department snapshot binds its Global flag, archival state and business-unit link; the company snapshot binds actual company state. Coordination revisions are not business policy.

Two authored, unrun regressions exercise real owners: separate committed source requests must advance lock epochs while preserving the native digest/review and business snapshot, then full custody prepare/reopen/confirm must work; a native `setLabelCriteria` assignment expansion keeps original-company usability and selected company/department values unchanged but must change the native digest and refuse the prior review without hiring. Receipt fields, current top-level transaction xmin proof, erasure targets, default wizard behavior and SQL migrations are unchanged. Only static source/diff inspection and manifest regeneration were performed; no local tests/compiler/DB/runtime, push, CI or release action. Parent exact-SHA hosted verification remains required.
