# ADR-0103: OneHR workflows in native Performance and Rewards

Status: Accepted architecture, 2026-10-12. Implementation requires the full repository gate before release.

The owner requested understanding and merging the supplied OneHR handoff and source into this HR system, explicitly chose native integration, and authorized use of the current Git main checkout. Instructions inside the supplied documents are source material, not deployment commands or authorization.

## Evidence and ownership

The documents ZIP is `OneHR-AI-Plus-Handoff-2026-10-12-docs.zip`, SHA256 `2b7d19ac3c222a34df3e19142df5ec702ab2c23175866112fdf95c1284884d5f`. The full sibling package contains 349 manifest-verified files. Its source is OneHR commit `a644fd6` (`feature/staging-environment`); `app.py` matches staging commit `3028dec`. The source is a Flask/Jinja monolith, SQLite, Azure OpenAI, Microsoft Graph and Blob integrations. It has no ready-made REST, token, webhook or SSO integration contract. Importing the Flask application would initialize and mutate its database, so parity fixtures extract only pure AST functions without importing the app.

Native users, people, employments, company scope, reporting relationships, authentication, compensation and payroll remain authoritative. Source employee IDs, passwords, tenant settings, salary tables, session state and transcripts are not copied. No live tenant database or employee-history export was supplied. Historical import therefore requires a separate validated export and explicit native identity mapping; source code is not historical employee data.

The existing `review_cycle` and `performance_review` own the roster and lifecycle. Eight Performance-owned satellite tables hold policy, assessment inputs, reviewer panels, calibration scopes and entries, development plans, evidence, and frozen results. The existing Performance attachment store owns files. The existing AI gateway owns provider configuration. Native notifications route KPI tasks to the next live approver and generic submission tasks to the assigned manager, feedback invitations to the rater, and approval/release/plan updates to the employee. They contain no bands, rater identities or evidence text and inherit native notification entitlement and email consent. Rewards owns classification review, monetary calculations, approvals and posting.

## Assessment rules and transitions

- Assessment rules are editable only in draft, then immutable. Operational windows can change while the cycle is open or in calibration, under native cycle-administrator scope, with a required reason and before/after audit. Closed cycles remain read-only, and deadline changes never reopen submitted answers or frozen assessments. Opening the native cycle snapshots the native company, grade, leadership framework and matching technical profile. Company deletion refuses retained assessment snapshots and calibration scopes, including after employee transfers; native company administration reads a tenant-scoped boolean without gaining access to private assessments. Technical profiles resolve explicit employment assignments, exact department/title/grade matches, a self-picked role, then title/grade and title fallbacks. Current and next-level skills use the source’s 1 and 1.5 weights. HR can replace an unstarted assignment; started answers are retained. HR reviews source defaults and imports the actual catalogue before opening; the package is not evidence of live tenant configuration.
- Fourteen independent windows use Malaysia offsets. Mid-year development review uses the current year; year-end plans use the next year. Goal progress and evidence remain usable throughout the year, including from historical assessment links.
- KPI definitions are employee draft → whole-scorecard proposal → assigned moderator approval or return. Weights total exactly 100%. The audited source assigns one moderator per line, owned by HR; employees cannot reroute it. Native historical chain fields remain readable for compatibility but new scorecards use one moderator. HR-owned company KPIs are filled and locked through an explicit preview/confirm flow and are exempt from employee result/evidence entry. Employee results submit once. The journey confirms moderated results and the calculated overall band atomically; the classic per-line path retains a separate overall confirmation. Changed actuals or calculated bands require reasons.
- Quarterly KPI check-ins retain a current trajectory status and append before/after audit history. They do not collect numeric actuals or produce performance ratings; check-in-only frozen records are excluded from Rewards facts.
- Mechanism A uses the highest met threshold, with a minimum rating of one. Mechanism B applies the inclusive zero gate and the source base/excellence formulas, including excess multipliers and less-is-better arithmetic. One company uses one mechanism; explicit company B bands select B. The source's less-is-better excellence example remains UNKNOWN pending an actual approved example; the implementation preserves source arithmetic rather than inventing policy.
- Technical self answers are retained. Manager overrides require reasons and are separately confirmed. Current statements weigh 1 and future statements 1.5.
- Leadership has seven principles and grade-tier statements. Numeric subjects need the configured valid-response minimum (source default four; target panel five). Non-numeric subjects use one line-manager response and cannot serve as raters. Panels use distinct active numeric-grade people. HR can assign a panel matrix without inventing reporting edges, including partial panels; manager assignment still validates native relationships and the valid-response minimum. Confirmation for a person’s own review is independent of their right to rate colleagues. Unsubmitted reviewers can decline or be replaced; submitted answers remain immutable. Employee assessment views never return rater identities, relationships, counts or individual responses. Invitation events do not use subject-readable audit scope, preventing employees from counting panel invitations through their audit access. Privileged native system-audit access remains governed by the existing audit policy.
- Potential normalizes each component before blending. Defaults use 40% leadership and 60% reviewed technical for source grades 12–23/H; an absent reviewed technical profile falls back to leadership, rather than zero. Grade normalization and valid-response requirements are explicit. Potential cutoffs and framework statements are configurable. The package's max-35 framework is not silently treated as the later unverified max-17.5 catalogue.
- Optional extreme-rater correction defaults off. It classifies the same rater's submitted answers across the cycle, adjusts that rater's own score, clamps it to the available maximum, then averages. It does not adjust another person's answer or overwrite submitted feedback.
- Calibration has explicit native reviewer grants and cohorts. Performance and potential have separate windows and locks. An unchanged assessment can pass through a locked tier without creating an override. HOD closes for an axis after BU/BG locks it; BU need not wait for HOD; BG can supersede unfinished lower tiers and lock each BU separately; the last BU lock completes the session. Group `after`, `replace` and advisory `blend` preserve their configured precedence. The journey’s Group view uses performance only. Precedence is final → Group → BG → BU → HOD → manager. Group supports individual locks. Group and final reviews do not inherit the BG window. Native cycle administrators can reopen unfinalized decisions with a required reason, outside cutoff windows; later confirmed tiers must reopen first to prevent an implicit pass-through changing without review. Frozen cohort members are preserved. Unlock removes only inherited pinned bands; explicit moves remain. Talent decisions are one shared per-review record across tiers, with independent PIP/promotion confirmations. PBT and potential reference curves use source boundaries and configurable tolerance; strict distribution overrides require reasons. A reviewer cannot decide their own assessment or retrieve their own entry through the calibration service. Individual Group locks do not require unrelated cohort members to have completed their assessments; strict distribution checks require an override reason if the visible distribution is incomplete.
- The source’s 15-cell person talent classification is authoritative and differs from its default nine-box presentation (notably High potential / UA performance). The optional 15-cell display remains available. Box defaults are provisional until locked. PIP, promotion and special reward are separately confirmed decisions. Promotion candidates come from an active nomination or consecutive-year standing rules and known native promotion history; a non-PIP classification alone never makes somebody eligible.
- Year-end development plans move private draft → shared → closed, with employee acknowledgement. Dates and career-conversation notes are optional as in source. Managers can make attributed edits to shared goals; closed definitions and manager remarks are immutable. Goal status/notes retain check-in history and can change through a matching active plan-year review even after plan closure. Career aspirations and mobility belong to a current per-employment profile, while each yearly plan retains its shared snapshot. The 70:20:10 structure is a development prompt, not an invented quota.
- Evidence has source kinds and a 1,200-character limit, draft/shared/retracted states, objective/skill/principle links, and corrections as new entries. Shared text is immutable. Attachments use native storage and access rules. Endorsements and disputes append attributed, immutable responses from the employee or assigned manager; they never automatically adjust a rating.

## Frozen results, authorization and releases

Finalization stores the resolved bands, distinct source tiers, talent category, explicit nominations, normalized scores, policy digest, anonymous principle summary and a provenance snapshot of scoring inputs and calibration decisions. The digest identifies that frozen assessment. Legacy numeric `overall_rating` remains null: it is not a second final-rating authority.

Inputs, submitted feedback and frozen results are protected against mutation. Frozen results release independently for performance, potential, talent and anonymous 360 summary, with explicit revocation and audit. Administrators can release and revoke each working component before finalization. Visibility grants are separate from immutable results. The employee projection derives the current highest locked band and anonymous agreement report at read time; it never exposes the intermediate decisions, scores, counts or rater identities. Pending competencies leave valid 360 potential available on its own, matching source `combined_potential`; reviewed competencies subsequently change the blend. Frozen results take precedence after finalization, and only those can enter Rewards. The internal SQL working projection is not executable by the application role and requires differential verification against the existing deterministic model. The source’s sign-off rating record and 43-column XLSX/About export are now prepared, with database and rendered-flow verification still pending. Records observe the native assessed grade and current identity at capture, retain the last sign-off/lock observation, and freeze when their cycle is archived. HR reads the stored record without recomputing it; write privileges are restricted to internal capture functions/triggers, and capture batches prioritize missing records before the oldest 300. RLS intersects the opening and current company administration scopes and excludes the actor’s own record. Calibration justifications and rater identities never enter the export contract. Internal SQL scoring must match all 156 source golden cases before release. The employee's security-definer projection returns only released components, never hidden calibration or raw source scores. Reports consume the native frozen labels and result reference instead of squeezing OneHR bands into the generic rating scale.

Services recheck module entitlement, live user state, native employment relationships and grants. Matrix managers receive only their assigned KPI lines. A restrictive policy on the native attachment store intersects its existing visibility with the OneHR evidence role, so broader native reporting access cannot expose files to a KPI-only moderator. Calibration projections expose only the assigned cohort. Security-definer helpers have fixed search paths, explicit EXECUTE grants and tenant/actor checks. Cross-parent identity references are validated by triggers. Revisions reject stale forms; locks serialize decisions and finalization. Generic review, calibration, release, feedback and compensation writers refuse OneHR cycles, preventing a second workflow from changing their decisions.

## Rewards boundary

Rewards reads a narrow immutable projection under its own fresh GR/admin authorization, exact company roster and reward year, excluding the actor's own person. Development/evidence-only records are excluded. An unassessed axis retains the existing Rewards fact rather than erasing it. It selects the latest assessment period and prefers year-end where periods coincide. A Performance grant is not conferred on a Rewards reviewer.

A Group Rewards reviewer explicitly imports finalized results into an annual draft unit. Import invalidates classification verification and earlier approvals. `Super Star`, `Star`, `Solid Core`, and `PIP/Improvement` map to SSTAR, STAR, SCORE and IMPRO. Only an explicitly confirmed PIP flag maps to PIP; existing case evidence and human case review remain intact. Promotion and special-reward nominations are shown as evidence for human recommendations, not automatic awards. The source result ID/digest actually imported is retained independently of later compensation/roster refreshes. Existing Rewards calculations, BU → BG → GR → CTRO → EC approvals and atomic native posting remain responsible for pay.

## AI

The gateway receives only authorized notes and shared evidence, with native PII redaction. The model proposes a closed list of evidence indices; deterministic adjudication resolves only existing passages, rejects unknown/duplicate references or oversized drafts, and silently discards failure. Fresh access and evidence are rechecked after the provider call. The native proposal ledger records the adjudication and input digest without storing evidence text. Extractive suggestions remain editable. The separately adjudicated private-draft command path below can update PM/TC drafts through the shared native writer; it has no final assessment or pay actions.

## Verification and operational consequences

Source parity fixtures include 156 scoring cases and all 15 person talent combinations, with source provenance. The initial deployed integration at 53d35b11 passed its full gate. New parity changes, including their RLS/workflow, conversation and layout tests, are unverified while the coordinated release holds the shared test environment. Existing green evidence must not be attributed to these later commits. The full release requires TypeScript, the complete chunked gate, Next build, shadow migration, rendered UI checks and proof of arrival on the target installation. A draft policy must be reviewed against the organization's actual catalogue and live business rules before opening a real cycle.

The source's obsolete Rewards/succession routes are not revived: source Rewards was removed, while the native Rewards module already owns those decisions. Six locale catalogues contain the new keys; the initial integration used English fallback and later parity changes translated selected new controls. This does not claim complete translation coverage. SMTP, Graph and Azure credentials are not transplanted; native infrastructure owns those concerns. No second Flask runtime or separate employee directory is deployed.

Opening company, grade and 360 statement snapshots remain immutable across native company transfers; calibration validates the review snapshot rather than the employee’s later placement. Rewards still resolves the employee’s current roster and company.

## Participation audit and native date mapping (2026-10-13, implementation unverified)

Source `participant_sql` / `participation` separates being assessed from assessing colleagues: active staff take part when their imported service is strictly greater than one year or their confirmation is on/before review opening. HR can add, remove or clear a cycle override. Removing somebody retains the assessment inputs; unconfirmed active numeric-grade raters remain eligible to assess others.

The native cycle opener and preview now share that confirmation predicate, in addition to the native cycle's explicit eligibility filters. Review opening, rather than the appraisal period's January start, is the cutoff. Performance owns a snapshot of the opening inclusion decision and a separately editable override per native employment/cycle. An explicit HR addition creates the kernel-owned review before initializing its assessment; it does not fabricate KPI targets or panels. Removing somebody hides their active review tasks and calibration entries and refuses new assessment writes, while retaining inputs and colleague-feedback assignments. Existing deployed reviews are grandfathered into the snapshot, so introducing the rule cannot silently withdraw existing reviews. Finalized participation is immutable.

**Mapping limitation:** the source stores an imported `years_of_service` number; native Employment owns hire and confirmation dates. New native cycles evaluate service strictly after the one-year hire anniversary at opening. This preserves the documented policy intent, but cannot reproduce a stale or manually supplied source service number. The source package contains no employee database or historical service values. Exact historical participant reconciliation therefore remains UNKNOWN until an identity-mapped export is provided. The native opening snapshot also deliberately stays fixed across later edits to employment facts; HR uses an explicit override to change this cycle's roster. These are native lifecycle adaptations, not claims of byte-for-byte source state parity.

## Conversation draft actions (2026-10-13, implementation unverified)

The source's PM/TC chat tools write drafts; the person presses the form's final confirmation. The native conversation now accepts a closed command vocabulary for KPI actuals/notes, explicit yes/no competency answers/remarks, and an overall remark. A provider identifies assigned item IDs and literal UTF-16 spans in the actor's message. Deterministic adjudication requires a unique exact item label, extracts all new values from those spans, enforces the native draft schema and remark ceiling, and rejects invented fields, formulas, foreign items, repeated updates or ambiguous labels. No model prose or computed figure enters a draft.

The existing private-draft writer rechecks identity, role, module, window, submission state and optimistic revisions inside the same transaction as the conversation append. A duplicate request returns the original reply. The client flushes pending widget saves before sending chat and refreshes the active widget after a draft update. Invalid proposals remain silent and use deterministic guidance; accepted/rejected span proposals enter the native proposal ledger without storing message text there. Final submission, approval, calibration, release and Rewards actions remain human decisions. This does not yet cover the source's setting, career, evidence, feedback and calibration tool suites or its generated summaries.

The active form and transcript now share one desktop scroll region above the composer, following the source journey's layout. Mobile uses page scrolling with a sticky composer and a modal contents drawer. Visual parity still requires the browser gate.

Scoped HR may correct the current career profile outside the employee window/share lock, including from an archived review, without rewriting the career snapshot attached to a yearly plan. A manager can start the separate attributed career comment on a blank profile; creating that placeholder grants no ability to write employee aspirations. HR can explicitly reopen a shared/closed yearly plan while retaining its goals and recorded conversation, clearing acknowledgment and incrementing its revision. Employee editing resumes only through the usual open-period and plan-year checks. HR can inspect its scoped draft plans; assigned managers continue to wait for sharing. These are source behavior corrections and require fresh RLS and UI verification.

Evidence drafts preserve absent slots on partial writes and expose the source’s title, impact, who, date precision, measurement and raised-with-subject fields. Shared words require a new author-owned correction; links can change independently. Endorse/dispute is one standing verdict per actor, and citations are one stance per actor/decision kind, with before/after native audit events. Manager observations are shared immediately; existing private manager drafts are not automatically exposed. Evidence read scope is subject/author/assigned manager, plus assigned KPI approvers and scoped calibration/HR readers only for shared KPI-linked items. A generic HR grant does not reveal unlinked personal evidence. Evidence files remain in the native `performance_attachment` store with an optional evidence edge, rather than introducing another blob owner. Their audience follows the entry and assigned KPI; a generic HR grant does not reveal unlinked personal files. The remaining source agent tool suites are still outstanding.

Feedback panels have the source’s configurable cap (default five, maximum twenty; letter-grade subjects keep a single line manager). Scoped HR can archive and restore submitted members while retaining their answers, or reset an active submission to a retained draft. Frozen assessments and closed cycles remain protected. Membership changes and resets revoke a released anonymous report atomically, with a subject-safe native audit event containing no rater identity or answer. Relationship labels and ordinary later submissions do not revoke it. Rating records continue to reflect their last sign-off/lock; panel edits do not silently recompute that stored observation.


The source file contract is four active files per evidence entry, two MiB each, with its twelve PDF/image/Office/CSV/text extensions. The existing ten-MiB native contract remains available to classic reviews. Direct KPI uploads create or reuse a shared, employee-authored recognition entry, including a file-only entry with no invented narrative. KPI proof is derived from that entry’s links; old direct attachment links remain compatible. A file on an unshared entry does not satisfy the standout-result proof requirement.

The native file writer validates the evidence owner and serializes the cap. Bytes and file identities are immutable. Author removal is a narrowly authorized, retained-storage operation: removed files disappear from ordinary reads, while submitted or finalized KPI proof cannot be removed. The database locks related assessments before rechecking removal, so submission and removal cannot race away required proof. Metadata-only privileged removal avoids making removed bytes readable merely to satisfy an update policy. Public execution is revoked; the routine validates the calling actor. File audit events omit private filenames. Shared recognition accepts additive files after submission, without rewriting shared words or the frozen result.

The employee workspace contributes its own pack-owned navigation entry. The native identity, module gate and skin remain authoritative, while the source’s 224-pixel navigator, module views, pending/done groups, embedded form and transcript, visible composer and record drawer are retained. Current records expose entered private figures to their owner and manager-approved detail without calibrated ratings; history exposes separately released final ratings, anonymous report words and published plan remarks. Manager plan comments publish at closure or after the planning year advances. The record trend considers the first six history rows before filtering released performance ratings.

Active-cycle module switches now preserve the stored work and approvals, and restore them when enabled again. Scoring rules remain fixed at opening. Explicit cycle archive may retain unfinished reviews, as in the source; it hides their active workspace tasks and makes assessment inputs read-only without creating finalized Rewards inputs. Existing signed rating observations freeze through the archive trigger. Multiple native company cycles are retained rather than globally archiving unrelated companies when one cycle opens.

The setting conversation now routes eligible-library additions/removals and literal weight/number/base-target edits through the same scorecard writer as the form. Administrator spreads and source binary-float rounding determine generated ladders. Providers cannot submit, approve, reroute moderators or introduce catalogue definitions or computed values. The scorecard and conversation append share one transaction and optimistic revision check.

The source Job_Profile/Job_Skills workbook is supported through the existing spreadsheet decoder, with explicit preview/apply tokens. Reimports retain skill and profile identities, update each supplied role’s requirements wholesale, preserve absent catalogue entries and leave assessment snapshots unchanged. Scoped HR can edit/deactivate profiles and pin/hide career routes in an active cycle. Assignment generation is a separate previewed action, preserving started/private answers and explicit HR mappings. Each cycle owns its catalogue; archived cycle catalogues remain unchanged. Source global role catalogues are adapted to the native cycle scope rather than introducing a competing organization master.

The career conversation now accepts literal profile fields, exact current-role choices and add/edit/remove operations on an employee’s draft development goals. No proposal can share a plan, acknowledge a conversation or write a manager decision. The original profile/plan writers run inside the conversation transaction, preserving optimistic versions and rollback on stale messages. Current career profile corrections after sharing leave the plan’s agreed career snapshot intact. Provider failure falls back to deterministic guidance without clearing the widget or saving proposed changes.

Calibration and guided-review switches are independent operational controls, defaulting on for older policies. Disabling calibration removes its workspace and blocks decisions without discarding previously confirmed bands. Disabling guided review hides its private conversation and leaves the native assessment form available; re-enabling restores the conversation. Database policies/triggers protect these writes as well as service guards.

Assigned 360 reviewers receive the guided conversation beside their feedback widget. A conversation context is bound to one native peer-feedback request; identical framework IDs for different colleagues cannot select a different subject. Literal observed/not-yet answers and principle comments update only that actor’s private draft. Submitting feedback remains a separate human action. Subject, manager, HR and other raters cannot read that private thread. Module switches hide and restore the saved contexts, and archived periods display as archived rather than finalized. The widgets remount on a saved draft revision so chat updates appear in the actual form after refresh.

Bulk panel operations reuse the individual panel writers in one transaction. The source manager/report/peer candidate engine and seeded ten-panel peer cap drive missing-panel and top-up previews. Top-ups retain scored and released panels; archived pairings are never auto-restored by the builder. The source CSV/XLSX subject/assessor/relationship import supports add and replace modes, retaining submitted responses and explicit restores. Preview validates the actual writes inside a rolled-back savepoint, so no assignment or audit event remains from a preview. Apply rechecks a digest of the people, rules, panels and requested changes. HR relationship edits preserve submitted answers and do not revoke an anonymous report by themselves. Source replace-mode deletion of retained submitted rows is deliberately not reproduced; native retained records protect their answers.

## Manager panel visibility (2026-10-26, D-TM-01)

A subject's line manager no longer reads `performance_onehr_panel` rows. Before migration 0620, the manager arm of `onehr_panel_read` let the application role return every rater's identity, answers and remark, even below the valid-response minimum. Migration 0620 removes that arm from the read and update policies. The tenant pin, subject exclusion, scoped-administrator arm, the rater's own live card and the insert policy are unchanged, so managers still nominate raters.

The manager reads and changes panel membership only through two security-definer helpers. Both pin the tenant and require the subject's live line manager. `app.onehr_manager_panel(review)` returns the request, rater employment, relationship, submitted/archived/reset timestamps and archive reason. It never returns answers, remarks or principle comments. `app.onehr_manager_panel_member(request, archived, relationship)` archives or restores an unsubmitted member and sets its relationship label. Submitted members, resets and archive reasons stay with scoped HR. The manager's review screen and panel assignment use these helpers, so their output is unchanged. Rater answers remain readable only by the rater, through their own live card, and by scoped HR.

Not addressed here: `app.onehr_assessment_inputs` still gives the manager per-rater leadership scores, without identities, for the potential calculation.
