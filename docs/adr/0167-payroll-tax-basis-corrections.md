# Historical income-tax basis corrections

Status: approved feedback929ea296 plan revision1; implementation candidate awaiting verification and human review. No release or statutory certification is implied.

The correction owner appends tax-basis revisions over exact saved payroll sources. Original transaction amounts, closed batch totals, issued payslips, PCB paid, payments, import provenance and prior statutory artifacts remain immutable. Latest reviewed item IDs, flags and classification values are retained alongside year-rule source/version and exemption-table evidence; a hash alone is not provenance.

An authorized payroll administrator selects one original employer, assessment year, inclusive January-through-month prefix and explicit eligible employment IDs. Dedicated configurable view/recalculate permissions and current principal/company checks govern every service and administrative SQL boundary. Narrow grant carriers never borrow broader roles. Historical company authority derives from original payroll batches, including transferred or departed employments. Tax-input readers retain the original payslip readership boundary so denying the administrative correction log cannot hide an effective basis from a permitted payroll calculation or own annual report.

The country pack reconciles exact original line amounts and deterministically replays month/cycle/run ownership. Missing source/mapping, unsupported noncash or LP provenance, unknown assessment-year rules, and unresolved later cap allocation refuse the whole employee. Capped replay requires original year-bound TP3 opening evidence, including a saved zero. Today's profile or a cleared TP3 is not that evidence. Uncapped changes do not import current TP3 values. Original salary and tax-category owners remain separate.

Previews expire before initial confirmation and reject changed sources, rules or settings. Each employee's full prefix, revisions and audit outcome commit atomically under history-before-access locks. Confirmations are idempotent. Bounded continuation rechecks authority, terminal state, any prior outcome and exact inputs under the same lock. Interrupted batches preserve successes and require an explicitly authorized review before fresh-preview retry; recovery never bypasses revoked access. Limits and detailed recovery behavior are documented in architecture/HISTORICAL-TAX-BASIS-CORRECTIONS.md.

Consumers are future payroll YTD/exemption accumulation, tax-only same-month normal/additional inputs, the separate corrected-basis worksheet audit view, and supported newly generated EA/CP8D/EA-derived reports. Original historical working remains original. EA routing still requires its complete original evidence; imported display lines do not create that evidence. Existing artifact bytes and filing statuses are unchanged. EPF/SOCSO/EIS wages do not receive tax-only overrides. Every new calculation/report records its exact correction references.

A changed source invalidates the overlay. Replacement supersedes only the exact payslip or its validated immutable import-record lineage, never another cycle in the same month. Repetition with identical consumer-relevant values is a no-op; previous-treatment display evidence does not create a new correction. Rollback must preserve readable correction provenance and a compatible effective-basis reader; reverting to uncorrected tax inputs silently is prohibited. Migration reservation, hosted verification, human staging review and separately authorized production deployment remain distinct.
