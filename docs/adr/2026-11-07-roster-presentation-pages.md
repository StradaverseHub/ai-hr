# Roster presentation pages and explicit complete targets

Status: proposed, pending hosted qualification.

## Context

The grid already paged its DOM. The server still read the whole authorized employee list, hydrated every matching employee's roster/default schedule/holiday/leave window, built a complete workbook template and serialized those facts before that client pagination. The individual editor narrowed one employee only after loading the company employee list. Generate rendered all employees as native options; Copy rendered each target as a hidden input.

The Roster population is the legacy RLS employee read, including its current assignment (`valid_to IS NULL AND superseded_at IS NULL`), excluding employments whose termination date is on or before today's HR date. Future termination remains visible. Name/code search is ECMAScript trimmed lowercase substring matching, including Unicode, literal percent/underscore/backslash and surrogate behavior. Grid dates do not redefine this current employee population.

## Decision

Use the shared native employee-choice owner with trusted server-only `terminatedAfter` and optional exact employment IDs. Generic employee-choice transport cannot provide these authority/population controls. Native population filters, deterministic name/ID ordering, exact count and independent represented organisation facets precede the bounded employee projection. An explicit `All` keeps the existing shared 2,000-row ceiling with its visible truncation notice and complete export link; it uses one server population read rather than repeated 200-row count/facet scans.

The Roster presentation owner opens one enforced REPEATABLE READ / READ ONLY transaction and proves the actual calling principal. The shared employee port, bounded occupation/label projection and canonical roster/default shift/holiday/approved leave reads all use that same transaction. The transaction linearizes at snapshot admission; the next request observes committed authority/data changes. No cross-request authority or data cache and no Access advisory read barrier is introduced.

The full artifact reader remains the owner for explicit whole exports and workbook templates. The ordinary page ships only a template URL; clicking Download Template performs the complete authorized read. Cell resolution, domain writes, money, effective schedule calculations and export semantics remain with their existing owners.

Generate server-renders at most 25 named native choices before hydration and preserves individually selected IDs across searches/pages. JavaScript enhances the picker; native POST browsing carries the exact bounded selection in the request body across searches and pages. Selecting all matching employees explicitly fetches complete minimal IDs, records that actual set and displays its count. One JSON field transports the set. Generate and Copy both use a native read-only POST prepare/review step, display the actual count and bounded names, and require a separate Confirm POST. One enforced read-only snapshot owns the complete review IDs and first 25 display names; the complete cursor never repeats count/facet scans. Every confirmation and Server Action unconditionally requires the exact nonempty JSON set; omitted flags or raw legacy fields cannot select an unrestricted path. It never resolves current filters at submission to silently include later arrivals. Submission refuses empty, malformed, duplicate, excess or no-longer-permitted prepared sets; existing canonical command admission still owns write authority and dependencies. The transport limit is 100,000 distinct canonical UUIDs / 4,000,002 UTF-8 bytes, refused rather than truncated. The configured Server Actions body limit is over 14 MB (the profile attachment owner), and installed Next 16.4.1 sets the multipart field limit to that same configured limit; the explicit roster payload fits both limits. The native POST parser accepts a closed URL-encoded form and bounds the actual stream at 6,000,000 bytes / 20 seconds before decoding (including percent-encoding overhead). Every POST requires same origin, a fresh scoped administrator and current company/team purpose. All output fields are escaped and private/no-store, and IDs remain in a bounded body rather than URLs or a process/persistent store.

Department intent shares one extracted canonical population definition with the old generator branch: the existing effective-dated `listEmployeesPage` assignment join and active (`terminated_on IS NULL`) status, plus the template company filter. This is deliberately distinct from the roster picker population. Preparation narrows that exact old population to the posted current company/team, reviews explicit IDs and carries department intent plus those exact IDs through canonical write admission. The new reviewed-subset seam is separate from the legacy `departmentId + employmentIds` precedence. It validates canonical UUIDs, duplicate/count/body limits, current native principal, administered companies and any canonical My Team query independently at core admission. After the original Access/configuration/subject lock order, it uses the same department population owner and team scope/search owner to refuse any departed reviewed member; it never adds new arrivals. Canonical date splitting and bulk calculation/write primitives remain unchanged. A tenant-global template cannot silently widen the posted company/team.

Expected command refusals have finite typed owners with their original messages. Native preparation and commands share the canonical date-range and resolved-template validators; browser-valid reversed, overlong and identical Copy ranges are refused before review. Native expected validation/closed-period/template/group refusals render escaped 422 responses (permission 403; dependency change 409), preserve body-only IDs and submitted date/shift/department/scope controls for re-preparation, and retain back navigation. Unknown storage/driver failures remain failures and are never rendered as validation or raw SQL.

## Verification

Hosted focused tests cover known stored/rest/usual cells against the full canonical reader; HR cutoff and future-ended membership; exact counts and past-end pages; represented facets; native company/foreign/manager/forged authority; one read snapshot across concurrent employment mutation; actual canonical SQL input bounds; sequential borrowed transaction readers with original-error propagation and no outstanding sibling on failure; separate progress behind an open Access writer with short lock/statement deadlines; invalid date bounds before transaction admission; and a native 50,000-retained-employment component timing report (40,000 current Roster members by fixture design).

Native no-JavaScript journey tests exercise bounded POST browsing, exact complete/department preparation, escaped review/counts, confirmed real writes, foreign/omitted/raw/oversized requests and a new hire remaining outside the reviewed set. Deterministic native tests queue confirmation at the canonical Access lock after read admission, commit a transfer or new hire through the lock-owning writer, and assert departed-member rollback or exact original-target writes. Additional native tests cover pre-review ranges, post-review archival/empty patterns/Duty Roster Control/shift-group changes, safe error controls, and unclassified storage failures. Public core tests exercise malformed/duplicate/oversized/foreign/forged/team/company reviewed seams and unchanged legacy both-field precedence. Rendered control tests cover bounded mounted results, persistent cross-page selection, complete 50,000-ID explicit selection without a proportional hidden-input DOM, empty/foreign/duplicate refusal, and later arrivals remaining outside a prepared Copy set. Existing template workbook-byte and grid render tests remain applicable. Focused/compiler/build evidence and staging acceptance are distinct from this source decision. Production remains held.
