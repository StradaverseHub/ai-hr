## Problem and invariant

The full gate discovers every tracked `.test.ts`/`.dom.test.tsx`, computes native
DB/NODB classification, partitions it and independently verifies all executed files
and assertions. This coverage owner must remain complete. Atcef47 the real runtime
test is classified NODB but requires exact focused-only admission, Linux systemd,
sudo and Nginx. Thirteen discovered database diagnostic files skip mandatory cases
unless their focused selection is exactly one file. The strict full verifier
correctly refuses both shapes. The notification prototype additionally creates a
fixed cluster-wide LOGIN: database namespaces alone cannot isolate it.

An infrastructure requirement is a scheduling annotation, never an exclusion,
skipped capability, caller-supplied permission or substitute focused PASS. Every
discovered file still belongs to exactly one normal full-CI unit, and every case
must execute and pass. Unknown files remain in the computed ordinary inventory.
Adding another controlled test requires registering its infrastructure/admission;
unregistered or legacy skipped cases cannot silently qualify the strict witness.
Planning and controller inventory tests also refuse any discovered focused-only
conditional guard, including a future unregistered unified/facet prototype. Its
owner must register and implement actual admission at accepted-source integration.

## Source and execution owners

controlled database files, the runtime host file and the notification file. An

The full runner preserves the existing initial role handshake and database

provisioning executes only fixed official Nginx apt commands, then records actual
PID1, sudo UID, Nginx path/version/binary hash and systemd version. No arbitrary
package, command, URL, role, source-selected profile or script is accepted.

The runner writes a closed0600 admission record bound to exact source/controller,

The test admission helper accepts no caller context or factory callback. It reads

controller-owned complete plan and verifies native prerequisites and every pinned

four real connection URLs to the canonical loopback worker database, expected
roles and port5433. The existing exact sole-file focused workflow remains a
separate development-only mode with its own evidence directory. There is no
full-to-focused fallback on malformed or missing full intent.
Focused selection itself also requires an actual sole file whenever an annotated
test is requested; fixed cluster roles cannot share a focused database cluster
with unrelated files.

## Witness and recovery

The full verifier requires one complete singleton invocation, its closed source-
bound prerequisite proof, unchanged native database health, all cases passing and
zero skipped/pending/todo cases. Binding run/attempt must match the independently
authenticated witness. Normal API validation of workflow395777276, trusted
main/alpha controller, fresh first successful attempt, exact candidate/baseline,
job inventory, artifact digests and complete reconstructed plan remains unchanged.
The environment/provisioning record alone grants no release authority. Native
runtime fixture output remains diagnostic: it does not prove an installed real
Next application or authorize deployment.

Successful unaffected singleton reports remain verifiable and retain their
original run/source identity through existing source, focused, repair and browser
recovery accounting. A failed or invalidated singleton cannot be replaced with a
generic focused result lacking the required full-unit infrastructure proof. That
replacement path currently refuses explicitly; this change does not invent a
recovery PASS or require rerunning successful unrelated units. A future dedicated
full-unit recovery producer/verifier needs its own reviewed contract.

The local gate cannot impersonate these authenticated hosted units. It refuses
before running a narrowed suite or issuing PASS, invalidating a clean same-source
local full receipt as FAIL. Impact selection of a singleton also refuses. This
matches the repository's standard hosted verification direction; no test is
removed from discovery to make a local gate green.
