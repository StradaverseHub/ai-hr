# ADR-0038 — Leave 2.0 (eligibility, multi-level approval, state holidays, accrual & grade depth)

- **Status:** Proposed (design only — no code yet). Each slice ships behind its own gate where it changes the leave computation/grant path; pure-additive config + UI slices need no flag.
- **Date:** 2026-06-22
- **Builds on:** the existing leave engine — `leave_type` / `leave_policy` / `leave_ledger` (append-only) / `leave_request`, `core/leave.ts` (`requestLeave`, `decideLeave`, `openLeaveYear`, holiday-aware `workingDays`), and the **sourced** Malaysia leave pack (`localization/my/leave.ts`: EA-1955 annual/sick/hospitalisation banding + maternity 98d / paternity 7d, Act A1651 2022). Reuses ADR-0021's `claim_attachment` pattern, ADR-0034 (notifications), the reporting graph + `assertCanDecide` (manager approval), and the floor-vs-policy `max()` resolution (ADR's leave-policy slice).
- **Pull-through from:** consultant **#18 (the only BLOCKER)** + **#25** + TT checklist R18 / R19 / R23 / R37.

## 1. Context

The leave **engine is sound but shallow**. What exists today is correct and sourced — statutory entitlement banding (EA-1955 s.60E annual, s.60F sick/hospitalisation, maternity, paternity), an append-only ledger, year-open grant + carry-forward, single-manager approval, national holidays in day-counting. That's enough for a 17-person firm; it is **not** enough for the deskless enterprise anchor (~4,500 staff, ~60 entities across states, graded workforce). The consultant — testing for that scale — flagged the depth gaps as the one **Blocker**.

A ground-truth audit (2026-06-22) of the gaps:

| # | Ask | Today | True gap |
|---|-----|-------|----------|
| 25 | Eligibility per type (maternity female-only; paternity married-male) | entitlement is service-year only; **`person` has no gender / marital-status field** | a **data-capture prerequisite** + eligibility config + request-time validation |
| 25 | Mandatory supporting documents (MC for sick) | `leave_request.reason` is free text; no attachment | new `leave_request_attachment` (mirror `claim_attachment`) + per-type `requiresDocument` |
| 18/19/25 | Multi-level approval (≥3) | single `decided_by_employment_id`; `assertCanDecide` = manager OR admin | configurable approval policy → instance steps → chain-aware `decideLeave` |
| 18 | Holiday groups by Malaysian state | `holiday` is `(tenant, country)`; **no state column; no work-state on anyone** | work-state capture + `holiday.state` + state-aware `workingDays` + 14-state seed |
| 18 | Earned/accrual vs lump-sum | all standing leave granted lump-sum at year-open | `leave_policy.accrual_method` + a monthly accrual cadence |
| 18 | Leave category by grade | `leave_policy` has no grade/position scoping | a grade concept + grade-scoped policy resolution |
| 18/R18 | Staff see ALL entitled balances | `/leave` shows own balances; not framed as "all entitled types" | UI |
| R23 | Calendar + applicant history when approving | none | approver-context read + calendar view |
| R37 | Per-language leave-type names | `leave_type.name` is plain text | `leave_type.i18n` jsonb (reuse `kb_document` pattern) |

**The two prerequisites worth calling out:** eligibility (#25) and state holidays (#18) are not just logic — the **data they gate on does not exist yet** (gender, marital status, work-state). Each slice that needs them carries a capture sub-step (hire form + `/me` + CSV importer).

## 2. Decision

Deliver Leave 2.0 as **six slices (2A–2F) over the existing engine**, not a rewrite. Make the statutory decisions up front (§4), and protect the EA-1955 floor as an invariant across every slice (§5). The heaviest two (2D accrual, 2E grade) are explicitly sequenced last and may be deferred without blocking the rest.

## 3. The slices

### 2A — Eligibility engine + mandatory documents (#25 — the validation engine)
- **Data capture (prereq):** add `person.gender` (`male | female | undisclosed`) + `person.marital_status` (`single | married | other`) — sensitive PII, ADR-0030 Layer-0 discipline (reference-not-cleartext in events). Surface on the hire form, `/me` (self-maintained, ESS-gated), and the CSV importer.
- **Config:** `leave_type` gains an `eligibility` jsonb — `{ gender?, maritalStatus?, minServiceMonths? }` — and a `requires_document` boolean.
- **Validation:** `requestLeave` rejects ineligible requests with a clear reason (maternity → female; paternity → married male with ≥12 months service; §4). New `leave_request_attachment` table (mirror `claim_attachment`: bytea, RLS `can_see_employment`); when `requires_document`, a request without an attachment is rejected (or flagged for the approver — decide in build). Events: `leave-request.rejected.ineligible`, attachment add.
- **Why first:** well-bounded, fully sourced, delivers the #25 validation ask, and the gender/marital capture is foundational for the rest.

### 2B — Multi-level approval chain (#18 / R19 / #25 workflow) — the biggest, phased
- **Model:** a configurable **approval policy** (an ordered list of approver *levels* — `direct_manager`, `hr_admin`, a named role, or a skip-level — scoped by leave-type and/or grade) → at request time, **instance steps** are generated → `decideLeave` advances the current step; the request is approved only when the final step clears. ≥3 levels becomes **data, not code**.
- **Phasing:** **2B-1** a fixed two-step (direct manager → HR) to ship the workflow + notifications fast; **2B-2** the configurable N-level policy + admin editor. Each step dispatches an ADR-0034 notification to the next approver and back to the employee on the final decision.
- **Risk:** this is the architecturally significant slice (state/chain, idempotency, reassignment when an approver leaves). Recommend its own sub-ADR if 2B-2 grows.

### 2C — State-specific holidays (#18 — MY correctness)
- **Data capture (prereq):** `employment.work_state` (nullable, falls back to the company's default state) — Malaysia's 13 states + 3 FT. Surface on hire/edit + CSV.
- **Schema:** `holiday.state` (nullable text; null = national). Applicable set for an employee = national ∪ their work-state. `workingDays` + the holiday range query become state-aware.
- **UI + seed:** admin holidays gets a state selector; seed the MY state public-holiday set (**sourced** per state — Sultan/Yang di-Pertua birthdays, state Islamic holidays, etc.).

### 2D — Earned/accrual vs lump-sum + leave cycle (#18) — heavy, deferrable
- `leave_policy.accrual_method` (`lump_sum | earned_monthly | earned_quarterly`) + a leave-cycle start month. Earned modes grant via a **monthly accrual cadence** (ledger writes on a schedule, pro-rated for joiners) instead of the year-open lump sum. Lump-sum stays the current path.
- **Floor invariant (§5):** earned accrual must still reach at least the EA-1955 floor across the year.

### 2E — Grade-based leave categories (#18) — heaviest, deferrable
- Introduce a **grade** concept (new `grade` catalog, or a band on `position`) → `leave_policy` scoping by grade → entitlement resolution picks the grade's policy (still `max(floor, policy)`). Needs an org-design decision (where grade lives) — likely its own scoping note.

### 2F — Leave UI depth (#18 / R18 / R23 / R37)
- **R18:** `/me` + `/leave` show **all entitled leave types** with balances (not just the ones with activity).
- **R23:** approver context — the applicant's recent leave history + balance + a team calendar shown alongside a pending request.
- **R37:** `leave_type.i18n` jsonb (reuse the `kb_document` localisation pattern) so leave-type names render per locale.

## 4. Statutory decisions (sourced — verify against the Act text at build)

- **Maternity** — a **female** employee; **98 consecutive days** (EA-1955 s.37, as amended by the Employment (Amendment) Act 2022 / Act A1651, eff 1 Jan 2023; the prior ≤5-surviving-children restriction was removed). Already in the pack (days); 2A adds the female-only gate.
- **Paternity** — a **married male** employee, employed **≥12 months** immediately before, **7 consecutive days**, up to 5 confinements (EA-1955 **s.60FA**, inserted by Act A1651, eff 1 Jan 2023). Already in the pack (days); 2A adds the married-male + service gate.
- **Approval levels are configuration, not statute** — the law mandates entitlement, not an approval chain; ≥3 levels is a tenant policy.
- **Holiday state model** — applicable holidays follow **work location (state)**; national holidays apply everywhere, state holidays only in that state. (Gazetted federal + state holidays; seed sourced per state.)
- **Accrual mode is contractual** — earned-vs-lump-sum is an employer policy; it may sit **at or above** the statutory floor, never below.

## 5. The floor invariant (NON-NEGOTIABLE)

Every Leave 2.0 feature preserves the **EA-1955 statutory floor**, exactly as the existing floor-vs-policy `max()` resolution already does — the same safe-by-construction stance as ADR-0033 (TOIL):
- Grade policies (2E) and accrual modes (2D) set entitlement **≥ floor**, never below.
- Eligibility gating (2A) never blocks a statutory entitlement an employee is legally due; it only enforces the type's lawful eligibility (e.g. maternity is, by statute, female-only).
- A configurable approval chain (2B) never silently drops a request; an unactioned request stays pending and is surfaced.

## 6. Sequencing

`2A → 2C → 2B → 2F → (2D, 2E deferrable)`.

**Recommended start: 2A** — it's the fully-sourced #25 validation engine, well-bounded, and its gender/marital capture is the foundation other slices reuse. 2C (state holidays) is the next discrete, high-correctness MY win. 2B (multi-level approval) is the enterprise-critical core of the Blocker but the heaviest — phase it (2B-1 then 2B-2). 2F is UI polish. 2D + 2E are the deepest and least urgent; defer unless the anchor needs them now.

**Alternative if the anchor's pain is approvals first:** start 2B-1 (manager→HR two-step) to unblock the enterprise workflow, then 2A.

## 7. Non-goals / risks

- **Non-goals (Leave 2.0):** leave encashment/payout (separate from TOIL), shift-based leave, a full absence-management suite. Grade (2E) may spin out its own org-design ADR.
- **Risk — statutory drift:** mitigated by §5 (floor invariant) + golden tests asserting floors hold under every grade/accrual/eligibility combination.
- **Risk — PII surface:** gender/marital/work-state are new sensitive fields; apply ADR-0030 Layer-0 (reference-not-cleartext in events) + the same RLS discipline.
- **Risk — approval-chain complexity:** mitigated by phasing (2B-1 fixed, 2B-2 configurable) and a possible sub-ADR for 2B-2.
- **Risk — sourcing:** the state-holiday seed (2C) and the eligibility rules (2A §4) must be verified against gazetted/official sources before they ship, not hardcoded from memory.
