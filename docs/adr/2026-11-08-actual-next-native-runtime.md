# Actual Next runtime through native generation admission

Status: proposed first same-build slice, not implemented or installed. Base: `948d99624972af736fc4d23f25b4b494737c7736`. Production remains held; staging requires the complete six-phase gate. This ADR allocates no migration or CI policy version.

## Context and inspected facts

The qualified immutable inventory now owns bounded descriptor-based pnpm links and the exact sharp/fontkit build aliases. Existing format2 build archives and receiver hashes must remain unchanged. The admission CHECKONLY prototype still walks every release descendant through the no-symlink/no-writable-child rule, verifies only source/build marker files as release identity, and has one global source/build per profile. It cannot yet accept an actual pnpm Next release and its runtime caches. Its native witness uses a fictional backend and correctly reports `nextApplicationVerified:false`.

`scripts/performance/system-runner.mjs` currently builds the actual application, directly spawns Next workers, and terminates HTTPS in a Node round-robin proxy. That is useful application evidence but does not exercise native Nginx, systemd or protected readiness/drain admission. Keep all original receipts and these distinct claims.

Installed Next is 16.4.1. Its self-hosting and deploymentId documentation and the actual implementation were read before this proposal. The filesystem cache writes image/fetch data under `.next/cache/images` and `.next/cache/fetch-cache`; normal response cache keys go through `getRouteCacheKey` and write under `.next/server/route-cache`. Immutable prerender seeds remain under `.next/server/app` or `pages`. Runtime configuration TypeScript is transformed in memory; making next.config or compiled server code writable is unnecessary. The framework also has process-local tag and memory caches: sharing files does not coordinate invalidation.

The current root uses React request memoization for human/session facts. The source audit found no active `use cache`, unstable_cache or ISR/revalidate declaration; that is a lead, not sufficient runtime proof. Actual build manifests and authenticated alternating-worker mutation/read tests must establish the supported dynamic HR behavior. Future persistent HR/fetch/ISR cache use requires its own correct invalidation owner; adding a shared directory is not that owner.

## Decision: one immutable native package and exact cache mounts

Use a root-owned native release package plus systemd mount namespaces. OCI would require a newly commissioned daemon/image/base/registry/network/mount/PID/cgroup trust boundary, change the current controller's direct native process/socket proof and add no demonstrated benefit to this narrow slice. The already-qualified inventory and existing systemd/Nginx owner make the native package the smaller sustainable extension. This is not a decision against containers for a later independently commissioned platform.

One cohort uses exactly one accepted source, exact compiled archive/manifest, complete dependency inventory, Node/runtime closure and build/action manifests. No worker rebuilds the source. A closed managed-Next profile wraps those exact existing format2 bytes; neither format2 wire/hash nor its legacy in-place installer is broadened. Existing profile version1 remains strict and unchanged. A separate version2 profile branch owns the new package/mount/resource facts. Both CHECKONLY modes remain non-installing. Actual staging adoption still needs the protected operator grant/lease/installation route; it cannot be inferred from a development root-owned fixture.

The proposed package identity binds:

- Actual source SHA and tracked source inventory; compiled `.next` format2 archive/manifest digests; dependency closure including each in-root link target and relevant native packages; lock digest; build ID; server-reference/action manifest digest; Node executable and installed system runtime identity.
- Complete actual source/runtime files needed at `process.cwd()`, including config, public assets, localization/statutory data, assets/fonts and external runtime modules. Standalone output/tracer assumptions are not substituted for the existing full package without proof. Secret dotenv files, source Git metadata, generated application caches and provider credentials are excluded.
- Root ownership and absence of group/other writes, special files and escaping/unknown links; only the existing canonical inventory's pnpm and sharp/fontkit link purposes. Marker files or a caller-supplied manifest alone are not accepted provenance.
- Fixed root-owned controller and inventory-module bytes, exact unit/command/environment sources, source/build/resource envelope and protected profile digest. Root verification reads descriptors and bytes only; it never imports or runs package application code as root.

Use an absolute root-owned release path such as `/opt/aihr/releases/<package-digest>` without a mutable current symlink. All units have that exact cwd and stock absolute Node -> verified Next CLI `start --hostname 127.0.0.1`. PORT comes only from the controller's root-owned EnvironmentFile; no pinned `-p 3000`, shell interpolation or wildcard bind. Bind the actual staging build runtime (currently Node22.23.3/ABI127/glibc2.39/Next16.4.1), not the older production Node24 observation.

All code/dependencies/build manifests, `.next/server/app`, `.next/server/pages`, static assets and parent directories are read-only. The root-created empty mountpoints below are the only Next writable exceptions:

| Target in each worker namespace | Root-declared source | Purpose |
| --- | --- | --- |
| `.next/cache/images` | `/var/cache/aihr/<cohort>/<slot>/images` | Official image optimizer data |
| `.next/cache/fetch-cache` | `/var/cache/aihr/<cohort>/<slot>/fetch-cache` | Official fetch cache data; no authorization or HR fact cache added |
| `.next/server/route-cache` | `/var/cache/aihr/<cohort>/<slot>/route-cache` | Official scoped response artifacts and immutable seed promotion |

Cache parents are root-owned, sources have the exact declared application UID and restrictive modes, and no symlink or source path from a request is permitted. Unit-private paths avoid assuming Next's process-local LRU/locking is a shared cache coordinator; they do not claim isolation between processes sharing an application UID. Caches carry no executable authority and are not returned in the package or release inventory. They may be discarded only after all owned processes/readers that can use them have positively quiesced. All other writes, including unknown Next cache paths, refuse rather than expanding a whole `.next/server` or release exception.

Use closed verified `ProtectSystem`/bind mount declarations and restrictive capabilities/namespaces for the nonroot application. The privileged controller hooks must retain their independently verified trusted-root boundary, outside application-controlled mounts/environment. Do not assume systemd `+` behavior: prove actual hook execution and worker mounts natively. General `secure_path` stays strict. A dedicated purpose-bound inspector verifies the actual worker's mount namespace through its already-bound PID/start identity and kernel `/proc` descriptors, exact source device/inode, read-only code mounts and three writable cache targets, with process identity rechecked afterward. Neither a unit text declaration nor a mountinfo string alone substitutes for the actual namespace/file proof. Application cannot remount, substitute a code source or alter privileged state/PORT/profile/Nginx modules.

Private runtime environment remains root-owned, bounded and fingerprinted, outside source and cache trees. Preserve existing native credentials-source restrictions and reject loader/interpreter/preload overrides, environment-file precedence surprises, duplicate protected keys and dotenv autoload from writable cwd/home. Web workers receive app-role DATABASE_URL and existing identity/config secrets, never migration-owner credentials. Tests use isolated fictional values and publish only approved identities/metrics, never environment bytes, cookies or keys.

## Same-build action and cache correctness boundary

Retain the current prohibition on `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY`; do not unlock a new runtime key override in this slice. All workers use the exact same immutable action manifest/effective cohort key with no override. Actual closure-bearing Server Actions must work when a form is rendered on one worker and submitted to another, including after same-build replacement. Successful ordinary POSTs alone are insufficient. A different action manifest/build, environment override or source is refused before admission. `deploymentId` can detect skew and cause reload; its `?dpl=` is not ingress routing and it does not make old action IDs compatible.

Build-manifest inspection retains the existing package privacy restriction: only /_not-found, /_global-error, /404 and /500 may be prerendered and dynamicRoutes must be empty. Do not silently allow new public/application seeds. A later intentionally static application page requires the existing explicit policy review. The new envelope consumes the cold exact format2 artifact; it never packages a warm route-cache. Creating the three empty root-owned mountpoints after exact format2 verification is a separately declared envelope operation, not an old receiver exception. Alternate two actual app workers for a real existing business mutation and subsequent reads, with the existing native DB owner establishing the committed result independently. Verify another company/user/tenant cannot see that data and an actual permission decrease takes effect on a fresh request. Exercise prefetch/RSC/navigation and default cache headers as well as full HTML. Do not use cache deletion, cache disabling, fake selectors or a shared-cache claim to make freshness pass.

No new cache handler, Redis dependency, data/auth snapshot cache or global cache switch is introduced. If actual current application behavior relies on cross-process invalidation that these tests cannot establish, the slice fails pending a properly modeled coordination solution. New ISR/use-cache/fetch contracts cannot inherit this dynamic-HR qualification silently.

Cross-source/build admission, rolling upgrade, rollback between builds and two-build action routing remain explicitly refused. Opening that boundary later requires authenticated per-generation release facts, version affinity, old/new assets and action-ID/closure/key compatibility, schema expand/contract compatibility, background-job payload/lease compatibility and bidirectional rollback tests. Same-build resource tests grant none of these.

## Resource envelope and native ingress

Resource comparison fixes aggregate resources, not per-worker limits that multiply with count. First proposed hosted profile: 4096 MiB total V8 old-space, 16 total web connections, 2048 total bounded waiting budget, one application slice with 400% aggregate CPU quota, MemoryHigh7168 MiB and MemoryMax8192 MiB. Per-worker heap/pool are 2048/8, 1024/4 and 512/2 for 2/4/8 workers. V8 old-space is not RSS; native buffers, Sharp, child/thread work and cold starts must fit actual slice memory pressure/headroom. Profile values are a proposal, never assumed safe because arithmetic divides.

The actual standard host/affinity/all ancestor quotas, cgroup swap/OOM/peak/current/events, per-worker whole-process RSS and slice CPU/pressure must be captured. Reserve the separate existing bounded PostgreSQL container, driver/Chromium and host headroom. Keep the PostgreSQL maximum and non-web connection reserve explicit; actual configured web pools must total16, with independently observed connections and no background/migration pool multiplication. Capacity or insufficient host headroom refuses startup; it does not raise the host size/heap or switch to a paid runner. Later production sizing uses fresh actual host/service limits and measured RSS, not this CI profile or the old16CPU/64GB hardware-only number.

Use the existing budget owner and CPU policy: 2 and4 workers may run normal CI comparisons;8 on a4-CPU host is an explicit workflow-preflight-only oversubscription diagnostic. It is not production-equivalent, sustained8-worker qualification or sizing. Production-sized8+ remains a separately authorized maintenance test after staging. All variants run the same frozen artifact, data, browser/request mix, warmup/steady interval and unchanged latency/error/outcome gates. Record every relevant non-web/background pool, service and active generation in the envelope. A rolling same-build replacement cannot exceed aggregate pool/memory reservations while old processes drain; either reserve overlap capacity explicitly inside the same envelope or stop-and-start the affected slot while ready peers serve. Do not briefly double the budget.

Use a single dedicated actual distro Nginx instance/unit and real TLS ingress in the owned hosted fixture. Preserve Host including port, verified HTTPS forwarding, cookies, upload limits, streaming, RSC and the existing WebSocket upgrade forwarding policy, unrelated vhosts and the unrelated8080 service. Disable automatic upstream replay for all methods; never retry an ambiguous action POST. Managed UP publication, revision proof, guarded reload/barrier, PID/cgroup/socket identity, old-reader drain, quiescence and conservative raw-bind cooling remain unchanged. Use a constant32-port fixture reservation for the8-unit maximum (bounded active/replacement/cooling occupancy); exhaustion still refuses, and capacity is not an infinite-churn guarantee. No direct Node proxy is used as native ingress evidence.

## Implementation ownership and delivery order

1. `deploy/admission/next_profile.py` owns the closed managed-Next package/cache/resource descriptor and actual namespace inventory. It reuses the exact shared runtime inventory, copied to the protected helper directory with an authenticated hash; no second symlink resolver. `controller.py` adds only a version2 dispatch to this owner and calls its worker-bound checks at reserve/admit/reconciliation boundaries; version1 behavior and all process/reader/raw-bind guards remain intact. Add source/protocol/native negative tests before adoption.
2. A new `deploy/admission/test_next_native.py` and `test/runtime-next-admission-native.test.ts` own the real built application/owned PostgreSQL/systemd/Nginx development fixture. Reuse safe host-fixture ownership/cleanup utilities by extraction only where identical; keep original fictional transport proof and its report unchanged. No fake backend or test-only application route is substituted for Next/auth/actions.
3. Add a native backend adapter to `scripts/performance/system-runner.mjs`, using the same stock managed runtime and existing system-load/browser collector; retain the old direct-spawn path explicitly as historical/development mode. `runtime-acceptance.mjs` gains a separately discriminated native-systemd shutdown/evidence contract, not a weaker general success branch. Bind every actual worker pool/config and preserve all error/Busy/crash/lock/original latency assertions. Existing fixed, source-bound nonroot transaction observers may be admitted only in a separate development profiling command whose exact argv/module closure is checked and whose report remains non-release; arbitrary NODE_OPTIONS/preloads stay forbidden. First native transport proof uses ordinary stock Next without those observers.
4. Root owns authenticated install-grant/lease/new install-mode wiring, CI policy and singleton admission/global inventories. This child proposes no new policy number, old installer bypass, migration ID, production command or permission. Actual staging installer adoption follows complete qualification, not the development fixture.

## Required hosted tests and acceptance

Run only standard hosted Actions after frozen-source independent review. No local app build/runtime/compiler/DB or target installation. Keep the existing fictional native240second process limit unchanged. The new actual-Next smoke has a separately reviewed proposed480second fixture bound with build/fixture provisioning outside it; the sustained native runner retains the existing workflow/browser/load budgets. A timeout records incomplete evidence, never an automatic budget increase. The actual build producer must run once with closed build DB/provider environment, then every cohort consumes that exact artifact; semantic2/4/8 comparison binds one shared artifact identity rather than three rebuilt artifacts with equal source. Each native job owns its physical PostgreSQL cluster and systemd/Nginx fixture; follow genuine native singleton admission, not fabricated focused-only flags or skipped checks.

Positive proof must include actual Next health/Home readiness and hydrated internal login/session/MFA journey; cold exclusion with an already-ready peer; exact source/build/dependency/Node/action/environment/mount/cgroup identities; official image optimization with Sharp and a permitted cache write; statutory/fontkit CJK PDF output; closure-bearing existing Server Action across two workers and same-build replacement; independent committed mutation/read/fresh-authority proof across workers; upload and download correctness; incremental streaming observed before completion; RSC/prefetch/six-locale controls; actual stock-Next handling of unsupported upgrades (no invented WebSocket echo route); exact native ingress headers/cookies/body limits; zero automatic POST replay; and unchanged all-module/browser/load gates. Health or headings alone do not establish usable pages.

Negative proof must include an escaping/cyclic/unapproved dependency link, code or manifest mutation, wrong source/build/action/runtime/command, writable compiled-code parent, replaced mount source/target or extra writable mount, missing/unwritable allowed cache, forged worker PID/old invocation, unsafe environment source/loader/action-key override, wrong effective PORT/bind address, invalid or oversubscribed aggregate resources, stale/denied human scope, cold/crashed process, revision/reload failure, drain expiry and retained cooling/reader endpoint. The previously qualified protocol/fake-native cases remain valid only for their original claims; new Next-specific faults must exercise actual Next, not relabel them.

Persist source/controller/build/package/profile identities, actual per-unit invocation/PID/start/mount/resources, native Nginx revisions/endpoint readers, browser proof, committed outcomes, strict latency/error/Busy/crash/lock metrics and redacted failures. Missing/aborted/planned assertions remain incomplete. Native graceful stop must be independently proved through systemd drain/exit/cgroup evidence; do not satisfy the old profiler SIGUSR2 check by inventing it. Cleanup touches only objects recorded by identity and preserves foreign/uncertain state. Cross-build and installation flags remain false. No release or phase-complete claim follows from one passing transport job.
