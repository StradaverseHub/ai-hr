# Leave inquiry: bounded browser navigation over the exact legacy population

Status: second checkpoint prepared; hosted verification and rendered/load qualification
are pending. Production remains on hold. This follows the native admission/read-frame
checkpoint; it does not replace or relabel its original baseline evidence.

The old pages sent every authorized employee to a client component, where only the
first 25 matching rows could appear. The selected employee context also enumerated
every employee. The new Leave-owned picker returns an exact total, at most 25 display
rows by default (maximum 200), represented catalogue facets and a separately admitted
selected identity. The actual pages pass that page to the existing shared panel;
subsequent reads use its optional module endpoint. Other consumers retain the original
endpoint and local/remote behavior.

## Population, ordering and authority

The picker intersects current native HR companies with the server's company context.
Mixed HR/employee grants cannot turn an employee-only company into an HR company.
No posted tenant, grants, population IDs or scope can replace that intersection.
The side-effect-free POST bounds and validates its body, requires same-origin requests,
keeps search out of its API URL, disables response caching and passes cancellation into
the read-only transaction. Existing picker URL state remains unchanged for tab carry.

This port requires an actual RR/RO physical transaction and fresh native principal
proof. Public calls own that transaction. The first page and canonical inquiry rows
share the page's admitted frame; no navigation row grants effect or financial authority.

Candidate enumeration reuses the exact legacy employee/person/company and NULL-ended,
unsuperseded-assignment joins, including ended employees, missing assignments and future
open assignments. It does not substitute the generic navigation population. Native
company, department, business-unit and ended/active predicates narrow work before
transfer. Search conservatively includes Unicode candidates and then applies the old
JavaScript lower/includes matcher, including literal SQL wildcard characters.

Only six minimal identity facts are enumerated for exact ICU company/name ordering.
One Collator per sort preserves the old base sensitivity and default-locale identity
tie. SQL collation, an arbitrary cap or a database name-only page cannot substitute for
that order. Only retained page identities receive ten-field display hydration; the
assignment identity preserves LEFT-join multiplicity. Native facets retain a complete
population count and represented catalogue identities. Browser payloads contain no
full workforce DTO array.

Selected inquiry contexts add an employee-ID predicate before display projection.
The records All frame requests selection-only context metadata; its count and picker
come from the complete minimal navigation population. Balance All membership still
requires a complete server-side metadata/eligibility population for exact financial
row counts. It remains separate from bounded browser choices and canonical page-only
money hydration. No financial formula, command lock, eligibility rule, source context,
as-of behavior or complete 10,000-row export contract changes.
