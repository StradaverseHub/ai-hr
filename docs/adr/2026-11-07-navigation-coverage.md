# Stable shell navigation declarations and honest coverage

Status: proposed source contract; hosted verification and runtime acceptance are separate evidence.

The shared shell resolver owns capability-based presentation. Page and service owners still adjudicate access. The catalogue calls that resolver once and binds its output to reviewed, literal business IDs. It adds no permissions, role inference, entitlement logic, or server capability queries.

`lib/navigation/catalogue.ts` composes the actual audience inventory, additional rows, V9 registries, Rewards pack descriptors and the canonical `SCOPED_LIFECYCLE_NAVIGATION` registry. Each reviewed selector locates an existing descriptor. Its explicit business ID and source key survive label or address changes; those changes require updating the selector/ledger snapshot while retaining the identity. New or ambiguous selectors fail closed. Runtime Performance admin substitution binds its original pack descriptor before reporting the latest cycle address. The default `/performance` entry is distinct from Performance & Talent. Click addresses preserve `navigationHref`, including the Leave Tracker calendar query. Disabled, retired/replaced and duplicate rows are retained as metadata and never counted as actionable coverage.

The JSON ledger is reviewed source, never generated or rewritten by the gate. Each entry records provenance, its reviewed address, an accountable owner and an honest uncovered reason. New destinations, removed/stale entries, duplicate IDs, missing provenance/placement, and unresolved runtime bindings fail structural integrity. Actual `app/**/page.*` files establish source route existence. Redirects, dynamic route shapes and apparent route factories are classified only as source facts, never permission or working-screen evidence.

There are two results. Structural integrity can pass with an explicit reviewed backlog. Required runtime acceptance cannot pass without candidate-bound executed usable-content evidence for every active destination and completion of the registry backlog. A scenario declaration, test file, source page, HTTP response or mere receipt-shaped object is not an execution receipt; the producer must supply truthful run/artifact references, the exact source, installation, time, outcome and independent content assertions. This checker validates evidence structure and binding; it does not authenticate external artifact contents or confer release authority. No runtime receipts are shipped in the initial ledger.

This is a bounded shell slice. Immediate in-page submenu/tab registries remain explicitly incomplete. Scoped probation/contracts declarations consume the shared inventory export by reference; the resolver remains the only owner of their page/configure/intake fact predicates. Neither owning subpaths nor scanning the whole page filesystem establishes complete application coverage. The existing selected 83-path performance manifest stays unchanged and is not relabelled as universal navigation coverage.

Verification is through the existing focused Actions workflow on standard hosted runners, selecting `test/navigation-catalogue.test.ts`, `test/navigation-coverage.test.ts` and the existing resolver/placement tests with whole-repository type checking. The read-only command is `node --import tsx scripts/performance/navigation-coverage.ts`; `--require-runtime` selects the deliberately stricter acceptance result. Set `AIHR_CANDIDATE_SHA` to the exact frozen candidate when assessing execution receipts. Focused tests do not authorize deployment.
