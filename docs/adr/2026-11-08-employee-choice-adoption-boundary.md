## One bounded successor

`test/performance/employee-choice-bounded-search-reader.ts` is a reviewable
successor of the unchanged classic reader, not an application import. The whole
inverse reconstructs every classic source byte from every successor source byte.
The complete-ID helper remains byte for byte unchanged.

The successor orders native candidates by the same database-default text
collation and UUID tuple used by native page projection, before any JavaScript
matching. It counts every exact match but retains only the requested page's IDs.
Projection receives those IDs with offset0 and the original limit/population;
the native owner independently rechecks the same principal/RLS/scope. Its count
must equal that bounded page's ID count. The returned total is the complete
JavaScript match count, including out-of-range pages. A page with no matches
starts no projection. The complete-ID helper still enumerates every matching ID.

No `localeCompare`, C collation, fuzzy/FTS/accent/NFC folding, substring truncation,
cache, new index, timeout, pool or native transform is introduced. The raw filter
and original `trim().toLowerCase()` query remain unchanged. Null codes, duplicate
names, distinct employments sharing a Person, literal `%`, `_`, backslash,
Unicode contexts, control characters, NUL, lone surrogates, safe offsets,
selected identity and full independent facets retain their contracts.

The native controls independently query base columns in actual native order and
apply the original JS predicate. They check the actual full_name column's
collation against the native text return type, capture actual dispatched SQL,
assert bounded projection IDs/offset0, compare both old owners, and check borrowed
snapshot identity, current revocations and exact restoration. Source checks
establish provenance and complete discovery only. Neither set has run here.
Sorting can add cost; this slice claims no measured gain. Candidate transfer and
full server scope transmission remain, so this is a partial structural change.
