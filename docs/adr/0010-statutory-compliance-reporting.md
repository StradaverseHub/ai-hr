# ADR-0010: Statutory & compliance reporting

**Status:** Proposed

**Supersedes:** none · **Related:** [0006](0006-event-and-audit-substrate.md) (event/audit substrate),
[0008](0008-localization-packs.md) (localization packs), [0009](0009-multi-company-group-model.md)
(per-company filing). See also [STATUTORY-SOURCES.md](../architecture/STATUTORY-SOURCES.md).

## Context

Payroll computes the right statutory figures — EPF, SOCSO, EIS and PCB (incl. bonus via the
additional-remuneration difference method) against the official 2026 tables — and we capture the
identifiers filings need (company: EPF employer no, SOCSO code, LHDN **E**-number, SSM, MyInvois
TIN; employee: IC, EPF/SOCSO/tax no, bank). **But we emit nothing an employer can submit.** A
codebase scan returns zero reports, exports, or filing files. For a commercial Malaysia-first HRMS
this is the largest remaining payroll gap — the numbers are computed but never turned into the
artefacts the law requires.

Malaysian employers must produce, **per legal entity**:

| Cadence | Artefact | Authority | Window |
|---|---|---|---|
| Monthly | **CP39** (MTD/PCB statement) | LHDN | 15th of following month |
| Monthly | **Borang A** contribution file | KWSP/EPF | 15th |
| Monthly | **SOCSO + EIS** contribution file (ASSIST) | PERKESO | 15th |
| Monthly | **Bank payment file** (salary credit) | bank | pay day |
| Annual | **EA form** (per employee) | employee | end of Feb |
| Annual | **Form E + CP8D** (employer return) | LHDN | 31 Mar |
| Event | **CP22** (new hire) · **CP22A** (cessation) · CP21 | LHDN | statutory windows |

Three forces shape the design:

1. **Compliance liability.** Exact agency file formats (KWSP fixed-width, PERKESO ASSIST CSV, CP39
   layout, bank-specific files) are byte-sensitive and change yearly. Shipping a wrong file is worse
   than shipping none — this is the same liability posture as the statutory *figures* (ADR-0008).
2. **Per-company filing.** Each legal entity files separately (ADR-0009). Group consolidation is for
   *management*, never for *submission*.
3. **Reproducibility / audit.** A filing must be reconstructable: which figures, which statutory
   table version, generated by whom, when — and never silently mutated after submission.

## Decision

Build a **statutory reporting module** with the following shape.

### 1. Reports live in the localization pack (ADR-0008 extension)

Each jurisdiction pack gains a `reports` registry — a list of `ReportDef`:

```ts
type ReportDef = {
  id: string;            // 'my.cp39' | 'my.ea' | 'my.form-e' | 'my.epf' | 'my.socso-eis' | 'my.bank'
  label: string;
  cadence: 'monthly' | 'annual' | 'event';
  scope: 'batch' | 'period' | 'year' | 'employment';
  requires: string[];    // employee/company fields needed (readiness check) e.g. ['taxNumber','icNumber']
  generate(ctx, params): Promise<ReportArtifact>;
};
```

The generic core never names CP39 or EA — it asks `packFor(country).reports`. This keeps
jurisdiction-specific formats out of the core, exactly as the calculators are.

### 2. Two output layers (manages compliance risk; lets us ship value early)

- **Layer A — Report (human-readable):** on-screen table + CSV of the figures + identifiers. Low
  risk, immediately useful (key into the portal, or hand to an accountant). Ships after normal review.
- **Layer B — Submission file (agency-exact):** the byte-exact fixed-width / CSV / XML the portal
  ingests. High risk; each format **sourced + verified + verify-flagged** (REPORT-FORMATS.md, sibling
  to STATUTORY-SOURCES.md) and shown as **"DRAFT — not for submission"** until an accountant confirms
  it against the live portal. Built per-format, incrementally.

The split means Layer A delivers the "what to remit" value fast, while Layer B's liability is added
one verified format at a time.

### 3. Generated filings are recorded as append-only artefacts

A `statutory_report` row per generation — **derived data, but persisted for audit/idempotency**:
`{ tenant_id, company_id, jurisdiction, report_type, period_kind, period_key, status
(draft|final|submitted|amended), statutory_version, row_count, totals jsonb, generated_by,
generated_at, file_hash? }`. RLS: `tenant_id = current AND app.is_admin_for(company_id)`. Each
generation appends a `statutory-report.generated` domain event (substrate discipline, ADR-0006);
submission appends `statutory-report.submitted`. Re-running produces a **new** artefact — a submitted
filing is never mutated; an amendment is a new versioned row + event.

### 4. Readiness check before emit (compliance guard)

A report validates `requires` against the in-scope employees/company first and surfaces **missing
fields per employee** (e.g. "3 employees missing tax number") instead of emitting a defective file.
No file is produced until the data is complete (or the user explicitly overrides for a Layer-A draft).

### 5. Per-company scope, group-aware

Every report takes a `companyId` and filters to that legal entity. The existing company-context
switcher selects it; a group admin can generate for any company in scope. Consolidated group views
remain management-only and are never emitted as a filing.

### 6. Cadence sources

- **Monthly** reports key off a **payroll batch** (or pay period) — the figures already exist on its
  payslips.
- **Annual** (EA, Form E/CP8D) **aggregate across the tax year's batches** per employee.
- **Event** (CP22/CP22A) are driven off the **domain-event log** — `employee.hired` →
  CP22 worklist item, `employment.terminated` → CP22A — surfaced as a compliance worklist, not a
  silent auto-file.

### 7. Verification posture

Layer A ships after normal review. Layer B files carry the ⚠️ DRAFT banner (same pattern as the
payroll figures) until human-verified, with per-format provenance in REPORT-FORMATS.md.

## Consequences

**Positive**

- Closes payroll's biggest gap: from "computes correct numbers" to "produces the filings employers
  submit" — the difference between a calculator and a usable HRMS.
- Compliance liability is contained: derived-and-versioned artefacts, per-format verify flags, and a
  readiness gate that refuses to emit bad files.
- Reuses existing substrate — localization packs, per-company scope, the event log, statutory
  versioning — rather than inventing new machinery.
- EA forms flow to the `/me` portal (employees self-serve their annual statement).

**Negative / risks**

- **Format churn:** agency formats change yearly and per bank → ongoing maintenance. Mitigated by the
  pack + version stamping + verify flags, but it is a standing cost.
- **Bank diversity:** payroll file formats are bank-specific (many). Start with one common format
  (generic CSV / a major bank / DuitNow-IBG), expand on demand.
- **Cross-employer PCB:** an employee with concurrent employments across group companies (ADR-0009)
  complicates CP39/Form E correctness — already a flagged gap; reporting surfaces it but does not
  solve it.
- **Not e-Invoicing:** MyInvois is revenue-side (sales invoices), out of scope here despite the TIN
  field; tracked separately if client billing is ever in scope.

## Scoring (proposed design)

| Dimension | Score | Note |
|---|---|---|
| Scalability | 8 | derived projections over existing payslip data; per-company partitioned |
| Maintainability | 7 | format churn is real, but isolated in the pack registry |
| Security | 8 | per-company RLS (`is_admin_for`); filings carry employee PII — admin-gated |
| Auditability | 9 | append-only artefacts + events + statutory-version stamp = reconstructable |
| Data integrity | 8 | readiness gate refuses incomplete files; immutable submitted filings |
| Regulatory compliance | 7 | Layer A ✓ fast; Layer B per-format verified; cross-employer PCB flagged |
| Enterprise readiness | 8 | the lift that makes payroll actually fileable |

## Implementation slices

- **6A — Substrate.** `statutory_report` table + RLS + migration; pack `reports` registry + core
  `reporting.ts` seam (list / readiness / run / persist + event); a "Compliance" UI shell (pick
  company + period + report → readiness → preview). Ship with **one** Layer-A report (monthly
  contribution summary). Tests: artefact + event + readiness.
- **6B — Monthly Layer-A complete.** PCB/CP39 view, EPF, SOCSO/EIS reports + CSV, per company.
- **6C — Annual.** EA form (per employee, + `/me` download) and Form E / CP8D (employer return) via
  tax-year aggregation.
- **6D — Layer-B agency files.** CP39 text, KWSP Borang A, PERKESO ASSIST, bank payment file — each
  sourced + verified + REPORT-FORMATS.md entry, added incrementally.
- **6E — Event-driven worklist.** CP22 / CP22A surfaced from the domain-event log.

## Alternatives rejected

- **Reports in the generic core.** Rejected — jurisdiction formats belong in the pack (ADR-0008);
  core stays jurisdiction-agnostic.
- **Emit only byte-exact agency files (skip Layer A).** Rejected — front-loads all the compliance
  liability and delays any value; the readable report is useful on day one.
- **Don't persist artefacts (regenerate on demand).** Rejected — loses audit/idempotency and the
  "what exactly did we submit, computed how" guarantee; filings are append-only by nature.
- **Auto-file CP22/CP22A from events.** Rejected for now — statutory submissions need human review;
  surface a worklist instead of silently transmitting.
