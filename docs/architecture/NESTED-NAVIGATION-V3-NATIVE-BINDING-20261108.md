## Smallest durable boundary

Keep all v2 files, scenarios, validators, historical receipts and existing runner
calls intact. Add an independent v3 protocol/scenario/collector bundle, initially
commissioned as a bounded functional preflight. Root owns later load integration.
The complete family/leaf/role matrix must be resolved before all-module acceptance.
A selected prototype is never renamed complete coverage.

Separate four owners:

1. Canonical UI/domain descriptors own stable definition IDs, native query/href
   builders and actual visibility/state. No descriptor grants permission.
2. A job-owned fictional constructor calls existing canonical domain helpers and
   records exact native returned identities, known input facts and ownership.
3. A closed native resolver verifies the actual principal/current domain owner
   and produces an opaque private binding in its owning process.
4. The browser adapter performs the native menu interaction and independently
   checks visible usable content, identity, outcome and actual timing.

Public scenario intents contain descriptor IDs and closed symbolic selectors
such as own-current, permitted-report, allowed-other-company, historical,
foreign-tenant, same-tenant-out-of-scope and nonexistent. They contain no caller
UUID, URL, SQL, principal role/grant object, script or verified flag. The resolver
maps those symbols to typed real records only after the native owner checks.
Do not derive semantic IDs from paths, translated labels or record UUIDs.

A private binding is a discriminated union of family-specific records, not a bag
of optional IDs: own-employment; workforce-employment; owned-draft; company;
schedule-rule; leave-type; probation-company; subsequently each reviewed domain
class. It binds actor index, actual user/person/tenant, subject/company, date/
version where relevant, source/run/attempt/fixture epoch and descriptor owner.
Bound route, client choice and record choice carry distinct types. A draft ID
cannot be used as an employment ID, nor a company as a rule/leave type/cycle.
Missing/foreign/unknown/stale/mismatched bindings fail closed and stay uncovered.

Private fixture JSON is only an allocation hint. Reuse the canonical principal
pattern already present in assistant-history-fixture: native
app.principal_by_identity(issuer,subject), resolveWorkosPrincipal and
withEntitlements, with exact expected user/person/tenant matches. This is the
existing internal-identity compatibility owner, not a new external login path.
For browser capture, additionally bind the actual current internal session and
unique signed-in account control; another person's name in workforce content
cannot qualify. Never fabricate roles/grants from the fixture's role label.

The production-facing resolver has no injectable verifier, callback factory,
caller-supplied seal or boolean that can mint a binding. A private WeakMap brand
is issued only after the fixed native read and source/resource admission; it
cannot be serialized and regained by JSON parsing. If native checking runs in
a separate fixed owned child, its actual source/profile/run/attempt/parent/native
completion and returned bytes must be verified before the parent can mint its
own handle. Reuse the qualified shared process kernel, not another process loop.
No provider, owner/migration credential or arbitrary command/SQL enters that child.

Native probes need a **single existing-budget app connection lease**, not an
import that silently initializes a second default full pool. Reuse canonical
reader/transaction/principal owners and preserve each purpose's isolation,
audit and refusal semantics. Do not turn an audited/config-initializing reader
into a read-only admission helper by dropping its effects or blanket RR wrapping.
If an owner lacks a suitable narrow projection, that domain requires its own
reviewed purpose API before binding; it remains blocked meanwhile. Root must
review this lease/factory seam before implementation. Max one backend is reserved
from the declared aggregate family budget, observed in normal telemetry; no new
independent pool, worker/resource allowance or elevated database role is allowed.

## Closed interactions and truthful outcomes

V3 steps are fixed typed operations: canonical menu link; named client choice;
bound record picker/search; existing disclosure/anchor; safe fixture field edit;
guarded unsaved transition; explicit discard; and a separately reviewed canonical
fixture save. No evaluate/program/selector callback is accepted from JSON.
Selectors are reviewed owner templates with typed binding slots and a finite
control vocabulary, never arbitrary data-supplied CSS. Existing trusted browser
introspection may check DOM state; it is not a user-program interface.

Wait for streaming elements inside the existing single remaining() budget, then
require a unique **visible**, enabled/actionable control. Scope each check to the
current native record and actual active panel. Multiple hidden mounted panels,
mobile/desktop duplicates, a heading, raw page text or a 200 response cannot qualify.
A client tab proves its actual active/aria relationship and unique visible panel,
nonempty independent native content and safe control. Route/anchor choices prove
the exact canonical address/target including allowed query/hash encoding. A
state-only step has no invented HTTP status or response requirement.

Query/fragment builders accept only the descriptor's typed parameter schema;
unknown/repeated parameters, alternate record, malformed mode, unexpected hash
and foreign origin refuse. Preserve native query order/carry and storage state.
Do not normalize away a dirty marker, unknown parameter or record mismatch just
to make URLs compare equal. Generic ClientTabs, Leave Type conditional bodies,
workspace selection and standalone V9 local-state routes need separate adapters.

Outcomes are separate: populated usable; explicitly valid-empty controls-only;
native readonly; hidden; native denied (the owner's exact redirect/403/404/gate,
not v2's universal '/' assumption); unsupported; unseeded; unbound; unrepresented
realm/role; and failed. A hidden menu requires both absence and a deliberate direct
native-admission refusal where applicable. Unsupported/empty cases can prove their
honest state, but cannot satisfy a populated/working-feature obligation. Unknown
availability never defaults to denied or skipped. Operator/invitation realms
require separate real actor/custody contracts; four HR roles cannot stand in.

Unsaved cases must observe the real existing guard, cancelled transition, retained
input and later commit/discard/ref/keyboard/tour semantics as applicable. Saved
cases use the normal UI server action, captured native identity/revision and an
independent canonical persisted read plus audit/count/money invariants. Restrict
initial writes to reversible fictional nonfinancial fields or owned drafts. Do
not submit provider prompts, payroll/financial actions, signatures, approvals or
outside communications merely to prove a menu. Their actual behavior needs its
own approved scenario and existing domain correctness checks.

## Timing, capacity and proof custody

Keep 90 seconds per scenario, 1,024 scenarios, eight steps, sixteen checks, four
HR roles, four real sign-ins, six loaded contexts, 500 HTTP users, current think/
ramp/steady duration, resources and existing failure/latency limits. Native
binding/waits/interaction/cleanup belong to the owned scenario lifetime; do not
hide a slow dependency outside its deadline. Also measure each route/choice to
usable content against the existing sub-second navigation/read goal; the
90-second failure timeout is not a performance pass. Actual Busy, unavailable,
500, console/page errors and blocking-lock acceptance stay strict and separate.

The current collector runs sequential role scenarios at the END of each loaded
browser's other journeys. Adding 38 or all remaining destinations there cannot
be presumed to fit the five-minute steady interval. Compile the complete resolved
matrix first, including role/record classes, all steps/checks and current actor
lanes. Refuse capacity if any obligation is unknown or cannot start AND become
usable at active=500 within that window. Do not silently add contexts, time,
workers, drop a role/leaf, omit existing journeys or replace per-role coverage
with a global union.

If needed, propose deterministic bounded v3 cohorts over separate otherwise
identical full workload runs. Each cohort requires both baseline and loaded
proof, frozen fixture/traffic protocol and exact planned coverage. Root must
approve that scheduling change before editing system-load. All 2/4/8 comparisons
must use the same new frozen cohort matrix on matching resources; old results
cannot be relabelled. Cross-run aggregation validates exact source/controller,
protocol/cohort plan, environment and required case identities; it does not imply
simultaneous full-scope execution or grant release authority.

V3 uses separate versioned scenario, capture, ledger and member names, retaining
all v2 decoding rules. Bind candidate/controller, exact native fixture/probe and
case-plan digest, family/descriptor owner closure, principal/record class,
source/build/run/attempt, actual context/interaction timings, outcome and failure
observations. Public evidence contains minimized symbolic bindings/counts/hashes,
not private tokens/credentials/raw HR data. Caller JSON cannot authenticate it.
Live API repository/workflow/controller/run/job/artifact digest/freshness checks
and the private verifier capability remain required. A feature-branch diagnostic
run is not accepted by weakening the current main/alpha trusted-controller rule;
root must commission the appropriate explicit trusted route. Release stays false.

V2's harness roots omit many new canonical fact/renderers. V3 must bind a reviewed
complete code closure and all canonical builders/probe/fixture/adapter/validator
owners, with the existing 2,048-file, 2 MiB-per-code-file and 32 MiB bounds. Every
parameterized association must have an explicit source owner, not an ID inferred
from a route template. Data/catalogue sources are also bound to the exact candidate
Git tree and actual build/source witness. Do not casually append raw locale files
to the old code-harness list: en is 2,134,182 bytes and ta 4,734,206 bytes, exceeding
that individual code limit. Proposed v3 representation binds their immutable Git
blob/tree identities as nonexecuted data inputs to the same actual build; root
must review that source-identity interface before implementation. No bound is
raised or omitted input presented as a full transitive source proof.
