## Native authority

The earlier partial prototype checked only that a proposed recipient belonged to
the event tenant. That was insufficient: the restricted LOGIN could address an
admitted payroll notice to an unrelated employee in that same tenant.

A private native reader now derives the exact audience for each admitted event and
canonical kind, using the existing fixed fact branches. A protected recipe and
indexed recipient relation bind that source-derived set to batch/event/kind inside
the actual backend/xid. The worker cannot insert, alter, select or grant these rows.
Both facts and project consume the same native capture; no caller-supplied array
or recipient claim can authorize another row. project checks indexed exact
membership, not only tenant membership. Capture happens once per recipe in that
transaction, matching the existing resolver-before-projection interval; it is not
reused across transactions or represented as a cache of later command authority.
Unsupported families still refuse instead of creating empty fabricated audiences.

The recipient relation deliberately has no Employment foreign key: validation and
actual notification insertion retain native existence/tenant/FK checks without
acquiring source key locks for an entire future audience before projecting it.
Batch/event foreign keys and mandatory same-transaction settlement remove the
protected temporary-in-purpose rows on finish or rollback. Native family results
containing an Employment outside the event tenant refuse rather than silently clip.

Payload-only exclusion rules have one declarative boolean description in the
canonical registry: overtime-only decisions, cancellation superseded by HR, and
Notice notifyOnPublish. The pure registry interprets those same descriptions; the
owner-installed closed contract supplies them to the native audience interpreter.
Missing/null/nonboolean values retain the prior strict true/false behavior. An
explicit point-projected Home greeting admits no worker recipient. All original
renderers, IDs, categories, date/delegation decisions and web RLS remain unchanged.

A known nonobsolete event cannot be ignored. A processed event must have projections
for every protected recipe/recipient; a caller cannot just mark pending work done.

processed, and unsupported reminder preparation remains blocked. The existing

## Render authority is explicitly trusted

The fixed API still accepts the canonical worker's rendered JSON proposal. Native
SQL enforces exactly title/body/linkPath/severity, finite lengths, allowed severity
and a local path without network-path, backslash or control-character escape. It
does not execute TypeScript's renderer or independently prove the semantics of a
well-formed title/body. A compromised LOGIN can propose different bounded text for
an actually authorized audience. This is deliberate bounded trusted-render authority,
not native content attestation or a no-fabricated-content guarantee.

The source keeps one canonical renderer; no hidden second SQL copy or self-reported
source digest is proof. Accepted protected source/build/runtime qualification must
later bind the executed renderer. A stronger native wording guarantee would need a
shared declarative render owner or independently protected rendering owner; that is
not silently invented by this prototype. No readiness/deployment gate is loosened.
