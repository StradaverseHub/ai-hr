本指南面向在 AI HR 中处理马来西亚每月薪资的人力资源管理员和薪资专员。读完后，你将了解如何设置员工的法定档案、创建并处理薪资批次、读懂 EPF/KWSP、SOCSO/PERKESO、EIS/SIP 和 PCB/MTD 是如何计算的、处理奖金、加班、无薪假和按比例计算、关闭批次使其变为不可更改，以及对离职员工执行最终薪资建议。你需要 **hr_admin** 或 **super_admin** 角色才能进入薪资模块。

## 运行薪资前：法定档案

薪资单上的每个数字都由员工的法定档案驱动。请先把它设置好，因为任何缺失必填数据的员工仍会出现在批次中，但扣款不完整。

1. 在左侧边栏中，点击 **People**，然后点击员工姓名以打开其详情页。
2. 找到 **Statutory (Malaysia)** 卡片（右列，紧邻 **Compensation**）。
3. 填写各字段，然后点击 **Save statutory**。

### Statutory (Malaysia) 卡片上的字段

| 字段 | 说明 |
| --- | --- |
| **IC number** | 必填。12 位数字（例如 `900101011234`）。每个租户内经过验证且唯一——空格和破折号会自动去除。 |
| **EPF number** | KWSP 会员号码。 |
| **SOCSO number** | PERKESO 号码。 |
| **Tax number** | LHDN 所得税（PCB）号码。 |
| **PCB category** | `1 — Single`、`2 — Married, spouse not working` 或 `3 — Married, spouse working`。驱动 MTD 减免。默认为 `1`。 |
| **Children (PCB relief)** | 符合 PCB 减免资格的子女人数。 |
| **Bank** / **Bank account** | 用于付款汇总导出。 |
| **EIS eligible** | 复选框。对于不在 SIP 覆盖范围内的员工取消勾选（例如 57 岁后首次缴款且无先前缴款记录）。 |
| **Tax resident** | 复选框。对于非居民取消勾选——他们按统一的 **30% MTD** 缴税且无任何减免。 |

### TP3 / 期初余额（仅限年中采用者）

**Previous employment this year (TP3 / opening balances)** 部分用于初始化 PCB 累计值，以便在年中开始使用 AI HR，或聘用本日历年已在其他地方工作过的人员时，MTD 计算正确。请从员工的 **Form TP3**（或你迁移前的薪资系统）中获取这些数字：

- **Applies to year** —— 这些余额所属的日历年（例如 `2026`）。只有当它与批次的薪资年份匹配时，余额才会被使用。
- **Accumulated net remuneration (Y−K)**
- **EPF claimed toward relief (K)**
- **PCB already deducted (X)**

**注意：** TP3 数字绝不会打印在薪资单或 EA 表上。它们只用于累计 PCB 计算。

**提示：** 薪资本身位于旁边的 **Compensation** 卡片上。在运行薪资前，请在那里使用 **Update pay** 设置 **Basic salary (MYR)** 和 **Allowance**——按比例计算和所有法定基数都会读取当前的薪酬记录。

## 创建薪资批次

1. 在左侧边栏中，点击 **Payroll**。你会进入 **Payroll Process** 选项卡，其中列出每个薪资流程及其 **Period**、**Company**、**Employees**、**Net pay** 和 **Status**。
2. 在薪资流程表底部，使用创建表单：
   - **Company** —— 选择要运行的公司。
   - **Pay period** —— 输入 `YYYY-MM`（例如 `2026-05`）。默认为当前月份。
3. 点击 **Create payroll process**。

新批次以 `Draft` 状态打开。**注意：** 每家公司每个薪资周期只能存在一个批次——对同一周期的第二次尝试会被拒绝。

## 草稿批次：输入项、加班、奖金

从列表中打开该批次。当它处于 `Draft` 状态时，你会看到一条琥珀色的合规免责声明、**离职员工建议**（如有），以及列出该周期内每位在职员工的**输入项编辑器**。

### 加班、奖金、TP1 和天课（按员工）

输入表中的每一行都有四个数字字段外加 **Save**：

- **OT** —— 手动输入的加班金额（RM）。
- **Bonus** —— 额外报酬（RM），例如合约奖金，或对离职员工而言为已折现的年假。
- **TP1** —— 员工的 TP1 扣减项（已核准、可减少 PCB 的税务减免）。
- **Zakat** —— 已缴天课，可抵减 PCB。

输入数值后，点击该行的 **Save**。最右侧的 **unpaid days** 列为只读。

**提示——从考勤预填加班：** 不必手动输入 OT，点击表格上方的 **Prefill OT**。AI HR 会读取该周期内已分类的考勤记录，并按雇佣法令的普通工资率（ORP = 月薪 ÷ 26）将其货币化：工作日 1.5×、休息日半天/全天规则外加 2×，以及假日规则外加 3×。月薪高于 **RM4,000** 的员工依法无资格享有加班费而被跳过——如需为他们支付任何特惠加班费，请在 **OT** 字段中手动输入。现有的 **Bonus** 数值在预填时会被保留；之后你仍可覆盖任何数字。

### 无薪假和按比例计算（自动）

这些你无需键入：

- **无薪假**由在该周期内**开始**的无薪假类型 `approved` 请求自动推导得出。它按普通工资率（月基本薪资 ÷ 当月天数）扣减。这是与 Leave 模块共享的单一事实来源——无需重复录入。
- 对于月中入职和离职者的**按比例计算**是自动的：基本薪资和津贴按当月实际受雇的日历天数缩放（EA 1955 s.18A 不完整月份基准）。薪资单会显示**工作天数**与当月总天数。

## 生成薪资单

1. 在批次处于 `Draft` 状态时，点击 **Generate payslips**（批次页面右上角）。
2. 批次转为 `Processed`，按员工的薪资单表格填充完成，并出现四项合计：**Total gross**、**Total deductions**、**Total net**、**Total employer cost**。

薪资单表格显示每位员工的 **Gross**、**Bonus**、**EPF**、**SOCSO**、**EIS**、**PCB** 和 **Net**。按比例计算的员工会就地标注其工作天数。

### 每项法定项目如何计算

| 缴款 | 基数 | 说明 |
| --- | --- | --- |
| **EPF / KWSP** | 基本 + 津贴 + **奖金**，**不含**加班 | 同时显示雇员和雇主份额。 |
| **SOCSO / PERKESO** | 含加班，**不含**奖金 | **60 岁及以上**的员工转入第二类别（仅雇主）。 |
| **EIS / SIP** | 含加班，**不含**奖金 | 覆盖适用于 18–60 岁；在 60 岁时或取消勾选 **EIS eligible** 时结束。 |
| **PCB / MTD** | 含加班和**奖金**（额外报酬差额法） | 采用 LHDN 累计法：PCB 类别、子女、TP1、天课和年初至今累计值（由 TP3 初始化）。非居民：统一 30%。 |

**注意：** PCB 年初至今累计值通过按顺序重放本税年早前的薪资单来重建，因此请始终在一个日历年内**按顺序**处理各月份，以确保 MTD 正确。

## 关闭批次（不可更改性）

1. 在批次处于 `Processed` 状态时，复核合计和薪资单。
2. 点击 **Close batch**。
3. 状态变为 `Closed`。

**已关闭的批次不可更改**——薪资单和合计被冻结以供审计。你无法再编辑输入项、预填 OT 或重新生成。如果在关闭后发现错误，请在下一个周期中更正。

**提示：** 从 `Processed` 或 `Closed` 批次导出银行文件——**Payment summary** 下载（右上角，一旦超过 `Draft` 阶段即可用）会生成一个中性的 CSV，包含员工、IC、银行、账户和净薪，供手动上传到你银行的门户。缺少银行资料的行会在导出中被标记。

## 离职员工的最终薪资建议

当你为某人办理离职时（在其 **People** 详情页的 **Terminate** 卡片上），且其最后一个工作日落在某批次的周期内，草稿批次会显示一条**离职员工**建议，列出**未使用的年假**、**每日 ORP**（基本 ÷ 26），以及**建议的**代通知金金额（EA 1955 s.60E）。

**这仅为建议——不会自动支付。** 如果你选择支付，请在生成薪资单前，将金额输入到该员工在输入项编辑器中的 **Bonus** 字段。AI HR 特意将决定权留给你，因为年假折现的 EPF/PCB 处理方式取决于你的政策。

## 常见陷阱

- **缺少 IC number** —— 如果 IC 不是 12 位数字，`Save statutory` 会被拒绝。请在运行薪资前修正。
- **未设置薪酬** —— 没有当前基本薪资的员工无法被货币化；请先通过 **Update pay** 设置。
- **乱序运行月份** —— 会破坏累计 PCB。请按 1 月 → 12 月的顺序处理。
- **高收入者与 OT** —— 任何月薪高于 RM4,000 的人都会被 **Prefill OT** 跳过；请手动输入任何酌情加班费。
- **关闭后编辑** —— 不可能。在点击 **Close batch** 前请核实合计。
- **重复批次** —— 每家公司每个 `YYYY-MM` 只能有一个批次；创建前请查看列表。
