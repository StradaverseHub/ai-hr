本指南面向**部门经理**——任何拥有 `manager` 角色且有直属下属的人。它将引导你了解统一的**审批**收件箱，你汇报线上的每一项请求都会在这里等待你作出唯一决定：请假申请、考勤更正申请，以及（针对管理员的）资料变更。读完本指南后，你将知道如何批准或拒绝每种类型的请求，明确你能看到谁的请求、为什么不能审批自己的请求，以及每次点击在后续会触发什么——比如扣减请假余额或修改考勤记录。

## 打开你的审批收件箱

在左侧边栏中，点击 **Approvals**。该页面仅对经理和管理员可见；如果你没有下属或管理员角色，则不会看到此菜单项。

在顶部你会看到一个标题为 **Approvals** 的 **PageHeader**。标题下方是一个实时计数：

- 如果没有任何待办事项，它会显示 **"Nothing waiting on you"**。
- 否则它会显示 **"3 items awaiting a decision"**（如果只有一项，则显示 **"1 item awaiting a decision"**）——这是所有分区的累计总数。

收件箱是一个屏幕，内含层叠排列的卡片。每张卡片的标题显示分区名称和一个计数徽章，让你一眼就能看出工作集中在哪里：

| 分区 | 内容 |
| --- | --- |
| **Leave requests** | 你下属的待处理休假申请 |
| **Attendance corrections** | 修正某日签到/签退时间的请求 |
| **Profile changes (bank / tax)** | 银行和税务明细的编辑——**仅限管理员**（作为普通经理你不会看到此卡片） |

**注意：** 此处仅显示**待处理**的项目。一旦你对某个请求作出决定，它就会从收件箱中消失——本页面没有"已决定"标签页。如需查看过往决定，请使用 **Audit trail**（管理员）或单条记录的 **History** 视图。

## 你能看到谁的请求（汇报线范围）

你始终只能看到**自己汇报线**上的请求——即在行政上向你汇报的人。系统在两个层面强制执行这一点，因此你无需手动筛选：

- **可见性**通过行级安全性进行裁剪：经理读取其下属的行，员工只读取自己的行，管理员则看到其范围内的所有内容。本页面上的列表在到达你之前就已经过筛选。
- **审批权限**是第二道更严格的检查（见下文）。

**提示：** 如果某位团队成员的请求没有显示出来，最常见的原因是你不是其**当前的行政经理**。汇报线必须在*今天*有效——未来生效、已结束或被取代的汇报线都不会把其请求送进你的收件箱。请联系你的 HR 管理员，在 **Org chart** 或 **Admin → Organization** 中确认汇报线。

## 禁止自我审批规则

你**无法审批自己的请求**。如果你自己的某个请求出现在列表中——例如，你为自己提交了一份考勤更正——操作列将不会显示按钮。取而代之的是，在通常出现 **Approve** / **Reject** 的位置，你会看到灰显的标签 **"your request"**。

这道防护设在服务层，而不仅仅是 UI 层，因此无法绕过。你自己的休假和更正必须由*你的*经理或 HR 管理员来审批。

**注意：** 这里有一个刻意保留的例外：`super_admin` 保留了唯一管理员的应急通道，*可以*自我审批，这样小公司里只有一人的管理员团队就不会被永久卡住。普通经理和 `hr_admin` 用户永远不能这样做。

## 批准或拒绝休假申请

**Leave requests** 卡片显示一个包含以下列的表格：**Employee**、**Type**、**Dates**、**Days** 和 **Action**。

1. 阅读该行：**Dates** 列以 `start → end` 形式显示日期范围，**Days** 显示计入的总天数（按工作日计算的休假类型已排除周末和公共假期）。
2. 在 **Action** 列中，点击 **Approve** 或 **Reject**。
3. 决定会立即提交，该行从收件箱中消失。

**Approve 在后续会触发什么：** 批准一项休假申请会在一个事务中原子性地完成三件事：

- 它会检查该员工对应休假类型的**预计余额**。如果批准会使余额降到零以下，则该决定会被阻止，显示 **"Leave rejected: insufficient balance"**，并且什么都不会改变。
- 如果余额充足，它会向只追加（append-only）的休假账本针对所申请的天数记入一笔**借项**（以休假开始日期为生效日），使余额恰好减少相应数额。
- 它会将请求状态翻转为 `approved`，盖上由谁决定及决定时间的印记，并在事件日志中记录该决定。

一经批准，这些天数在所覆盖日期的 **Attendance** 视图中也会计为**休假中**——因此该员工不会被标记为缺勤。

**Reject 会触发什么：** 状态翻转为 `rejected` 并记录该决定。**不会触及任何余额**——拒绝绝不会借记或贷记天数。

**常见陷阱——"余额不足"：** 如果 Approve 因余额失败，通常意味着该员工的权益尚未授予，或他们已经用完。你无法在此屏幕上覆盖余额；请将其转交你的 HR 管理员，由其记入一笔休假调整。

## 批准或拒绝考勤更正

当某员工的打卡时间有误时（忘记打卡上班、下班打卡过晚等），他们会从自己的工作区发起一项更正。它会落入你的 **Attendance corrections** 卡片。

表格列为：**Employee**、**Date**、**Proposed**、**Reason** 和 **Action**。

1. 查看 **Proposed** 列——它以 `HH:MM` 形式显示所申请的时间（包含签退时则显示为 `HH:MM → HH:MM`）。
2. 阅读该员工给出的 **Reason**（如果他们留空，则显示 `—`）。
3. 点击 **Approve** 或 **Reject**。

**Approve 在后续会触发什么：** 批准并非只是对时间盖橡皮图章——它会**通过时间引擎重建考勤记录**。所提议的签到/签退时间会按日类型（工作日、休息日或公共假期）重新分类，并重新推导出一个状态（`present`、`late` 或 `half_day`）以及**工作分钟数和加班分钟数**。这条更正后的记录会写入当日（替换该日期的任何现有行）并标记为 **"Corrected"**。由于加班在此处被重新计算，一项已批准的更正会直接流转到工资系统——因此把时间填对很重要。

**Reject 会触发什么：** 该更正被标记为 `rejected` 并记录；原始考勤记录保持不变。

**提示：** 加班分类遵循马来西亚 EA 1955 规则——休息日或公共假期的工作全额计为加班，之后在工资计算中按溢价费率折算成金额。因此批准一项休息日更正可能会合法地增加某人的工资。在批准前，请对照 **Reason** 核对 **Proposed** 时间是否合理。

## 资料变更（仅限管理员）

如果你同时拥有管理员角色，则会出现第三张卡片——**Profile changes (bank / tax)**。它列出对敏感字段的待处理自助编辑，显示员工姓名以及每项所提议的变更，形式为 `field → new value`。以相同方式点击 **Approve** 或 **Reject**。普通经理看不到此卡片；银行和税务变更保留给 HR 管理员，因为它们关联到法定扣款和付款文件。

## 快速参考：每项决定会触发什么

| 请求类型 | Approve | Reject |
| --- | --- | --- |
| **Leave** | 检查余额 → 记入账本借项 → 标记为 `approved`；这些天数现在在 Attendance 中计为休假中 | 标记为 `rejected`；**不**改变余额 |
| **Attendance correction** | 通过时间引擎重新推导当日、写入更正后的记录（含供工资系统使用的 OT）、标记为 `approved` | 标记为 `rejected`；原始记录保持不变 |
| **Profile change**（管理员） | 应用新的银行/税务值，标记为 `approved` | 标记为 `rejected`；不应用任何变更 |

## 故障排查

- **"You cannot decide your own ..."** ——你试图对自己的请求采取操作。这是预期行为；它必须交给你的经理或 HR 管理员。（只有 `super_admin` 才能自我审批。）
- **"Only an admin or the administrative manager can decide this ..."** ——你不是该对象*当前*的行政经理。请确认汇报线在今天有效且未被取代。
- **"... is already approved / rejected"** ——有人（通常是某位管理员，或你在另一个标签页里）已经作出了决定。刷新页面；它应该已从收件箱中消失。
- **某项请求始终没有送达我** ——请在 **Org chart** 上检查汇报线。如果它是未来生效或已结束的，请联系你的 HR 管理员在 **Admin → Organization** 中修正。

**注意：** 你作出的每项决定都会以你作为真实操作者的身份记录在审计/事件日志中——这里的审批是有据可查的，而非匿名的。如果你需要回顾谁决定了什么，那就是查阅之处。
