File format

Three columns (header names are flexible / case-insensitive):

Subject Employee IDAssessor Employee IDRelationship
100001100045line_manager
100001100052peer
100001100120direct_report

Relationship accepts: line_manager / manager, matrix_manager / matrix, peer / peer/stakeholder / stakeholder, direct_report / report (case-insensitive). People are matched by Employee ID first, then exact full name. A subject can have at most one line manager, but any number of matrix managers.

Safety rules. Four steps: choose the file, OneHR checks it, shows what it changes and asks the super admin about any pairing archived earlier, then you apply that same file. It is all-or-nothing: the whole upload is refused (no rows committed) if any row references an unknown Employee ID, is outside your Business Group, has a bad relationship, is a self-assessment, or — in Replace mode — would wipe an assessor who has already submitted feedback. The flash on failure lists every affected row so you can fix the file and re-upload.

Org-chart guardrail. A line_manager or direct_report row must agree with that person's Line Manager on the user list (Manage → Users). If the two disagree, the row is rejected with the name the user list currently shows — fix the user list first (or correct the row) before re-uploading. A person with no Line Manager on file can't be checked, so those rows go through as-is. If a row sets a NEW line manager for someone who already has a different one, the outgoing line manager is automatically reassigned to Matrix manager — never removed by a file import.
